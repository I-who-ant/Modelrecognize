## 📌 基本定义

**序列生成 (Sequence Generation)** 是指给定源序列，生成目标序列的任务。核心问题是如何选择最优的输出序列。

### 问题背景

```
序列生成任务:
════════════

输入: 源序列 x = [x₁, x₂, ..., xₙ]
输出: 目标序列 y = [y₁, y₂, ..., yₘ]

示例:
────

机器翻译:
  输入: "I love you" (英文)
  输出: "我爱你" (中文)

文本摘要:
  输入: 长文章 (500词)
  输出: 摘要 (50词)

对话生成:
  输入: "你好吗？"
  输出: "我很好，谢谢！"

图像描述:
  输入: 图像
  输出: "一只猫坐在沙发上"

核心挑战:
════════

问题: 如何选择"最好的"输出序列？

假设词汇表大小 V = 10,000
目标序列长度 m = 10

可能的序列数量:
  V^m = 10,000^10 = 10^40

这是天文数字！
无法枚举所有可能的序列
→ 需要高效的搜索算法
```

## 🎯 基础序列生成模型 (Seq2Seq)

### Encoder-Decoder 架构

```
基本架构:
════════

编码器 (Encoder):
  将源序列编码为固定长度的上下文向量

  输入: x = [x₁, x₂, ..., xₙ]
    ↓
  [RNN/LSTM/GRU]
    ↓
  输出: 上下文向量 c ∈ ℝ^d
       (通常是最后的隐藏状态)

解码器 (Decoder):
  根据上下文向量逐步生成目标序列

  输入: 上下文 c
    ↓
  [RNN/LSTM/GRU]
    ↓
  输出: y = [y₁, y₂, ..., yₘ]

完整流程:
════════

           Encoder                  Decoder
           ────────                ────────
  x₁  x₂  x₃  <EOS>              <SOS> y₁  y₂  y₃ <EOS>
   ↓   ↓   ↓   ↓                   ↓    ↓   ↓   ↓   ↓
  [h₁][h₂][h₃][h₄]               [s₀][s₁][s₂][s₃][s₄]
                ↓                   ↑    ↓   ↓   ↓   ↓
           上下文 c ────────────────┘    P₁  P₂  P₃  P₄
                                        ↓   ↓   ↓   ↓
                                        y₁  y₂  y₃ <EOS>

示例 (机器翻译):
───────────────

输入: "I love you"

Encoder:
  I    → h₁
  love → h₂
  you  → h₃
  <EOS>→ h₄ = c (上下文向量)

Decoder:
  s₀ = f(c)           (初始状态)
  s₁ = f(s₀, <SOS>)   (从开始符号开始)
  P₁ = softmax(W·s₁)  (第一个词的概率分布)
  y₁ = argmax(P₁) = "我"

  s₂ = f(s₁, y₁)      (基于前一个词)
  P₂ = softmax(W·s₂)
  y₂ = argmax(P₂) = "爱"

  s₃ = f(s₂, y₂)
  P₃ = softmax(W·s₃)
  y₃ = argmax(P₃) = "你"

  s₄ = f(s₃, y₃)
  P₄ = softmax(W·s₄)
  y₄ = argmax(P₄) = "<EOS>"

输出: "我爱你"
```

### 概率建模

```
数学表达:
════════

目标: 找到概率最大的输出序列

P(y | x) = P(y₁, y₂, ..., yₘ | x)

根据链式法则:
  P(y | x) = P(y₁|x) · P(y₂|x,y₁) · P(y₃|x,y₁,y₂) · ... · P(yₘ|x,y₁,...,yₘ₋₁)

           = ∏ᵢ₌₁ᵐ P(yᵢ | x, y₁, ..., yᵢ₋₁)

我们的目标:
  y* = argmax P(y | x)
       y

   = argmax ∏ᵢ₌₁ᵐ P(yᵢ | x, y₁, ..., yᵢ₋₁)
       y

   = argmax Σᵢ₌₁ᵐ log P(yᵢ | x, y₁, ..., yᵢ₋₁)  (取对数)
       y

示例:
────

假设生成 "我爱你":

P(我爱你 | "I love you")
  = P(我 | <SOS>, c)
    × P(爱 | <SOS>, 我, c)
    × P(你 | <SOS>, 我, 爱, c)
    × P(<EOS> | <SOS>, 我, 爱, 你, c)

  = 0.6 × 0.8 × 0.7 × 0.9
  = 0.3024

log P = log(0.6) + log(0.8) + log(0.7) + log(0.9)
      = -0.51 + (-0.22) + (-0.36) + (-0.11)
      = -1.20
```

## 🔍 选择最可能句子：解码策略

### 策略 1: 贪心搜索 (Greedy Search)

```
核心思想:
════════

每一步选择概率最高的词
不考虑全局最优性

算法流程:
════════

1. 初始化: y₀ = <SOS>
2. 对于 t = 1, 2, ..., T:
   a. 计算概率分布: P(· | x, y₁, ..., yₜ₋₁)
   b. 选择最大概率: yₜ = argmax P(w | x, y₁, ..., yₜ₋₁)
                          w∈V
   c. 如果 yₜ = <EOS>, 停止
3. 输出: y = [y₁, y₂, ..., yₜ]

伪代码:
──────

```python
def greedy_search(encoder_output, decoder, max_len=50):
    """贪心搜索解码"""
    # 初始化
    y = [<SOS>]
    hidden = decoder.init_hidden(encoder_output)

    for t in range(max_len):
        # 计算概率分布
        probs, hidden = decoder(y[-1], hidden)
        # probs: [vocab_size]

        # 选择概率最高的词
        next_word = torch.argmax(probs)

        # 添加到序列
        y.append(next_word)

        # 如果生成结束符,停止
        if next_word == <EOS>:
            break

    return y
```

示例:
────

机器翻译: "I love you" → ?

步骤 1:
  输入: <SOS>
  P("我") = 0.6  ← 最高
  P("你") = 0.1
  P("爱") = 0.2
  P("他") = 0.1
  选择: "我"

步骤 2:
  输入: 我
  P("爱") = 0.8  ← 最高
  P("喜欢") = 0.1
  P("恨") = 0.05
  P("看") = 0.05
  选择: "爱"

步骤 3:
  输入: 我 爱
  P("你") = 0.7  ← 最高
  P("他") = 0.2
  P("她") = 0.1
  选择: "你"

步骤 4:
  输入: 我 爱 你
  P(<EOS>) = 0.9  ← 最高
  选择: <EOS>

输出: "我爱你"

优点:
────

✅ 简单快速
✅ 每步只需要 O(V) 计算
✅ 总复杂度 O(T × V)
✅ 内存占用小

缺点:
────

❌ 局部最优 ≠ 全局最优
❌ 无法回溯
❌ 容易陷入次优解

问题示例:
────────

贪心搜索可能生成:
  "我 非常 爱 你"
  log P = -0.5 + (-1.2) + (-0.3) + (-0.1) = -2.1

但全局最优是:
  "我 爱 你"
  log P = -0.6 + (-0.2) + (-0.1) = -0.9  ← 更好！

原因:
  第一步选择 "非常" (P=0.7) 比 "爱" (P=0.6) 概率高
  但导致后续概率降低
  总体概率反而更低
```

### 策略 2: 穷举搜索 (Exhaustive Search)

```
核心思想:
════════

枚举所有可能的序列
选择概率最高的

算法:
════

对所有长度为 m 的序列 y:
  计算 P(y | x)
选择: y* = argmax P(y | x)
              y

复杂度:
──────

假设:
  词汇表大小 V = 10,000
  序列长度 m = 10

需要评估的序列数:
  V^m = 10,000^10 = 10^40

即使每秒评估 10^9 个序列
需要时间:
  10^40 / 10^9 = 10^31 秒
            = 3.17 × 10^23 年
            = 宇宙年龄的 10^13 倍 !!!

结论:
  ❌ 完全不可行
  ❌ 即使量子计算机也无法完成
```

## ⚡ 束搜索 (Beam Search)

### 核心思想

```
折中方案:
════════

不是每步只保留 1 个候选 (贪心)
也不是保留所有候选 (穷举)
而是保留 k 个最佳候选 (束搜索)

k = beam size (束宽)

示例:
────

k = 1: 贪心搜索
k = V: 穷举搜索 (理论上)
k = 3-10: 实践中常用

权衡:
  k ↑ → 更接近全局最优 → 计算量 ↑
  k ↓ → 更快 → 可能陷入局部最优
```

---

### 算法流程

```
Beam Search 算法:
═════════════════

参数:
  k: beam size (束宽)
  V: 词汇表大小
  T: 最大生成长度

步骤:
════

步骤 0: 初始化
  candidates = [(<SOS>,)]  (1个候选)
  scores = [0.0]           (对数概率)

步骤 1: 扩展第一个词
  对每个候选 c 和每个词 w ∈ V:
    新候选 c' = c + (w,)
    新分数 s' = s + log P(w | x, c)

  保留前 k 个:
    candidates = top_k(所有新候选, k)

步骤 2, 3, ..., T: 重复扩展
  对每个候选 c 和每个词 w ∈ V:
    新候选 c' = c + (w,)
    新分数 s' = s + log P(w | x, c)

  保留前 k 个:
    candidates = top_k(所有新候选, k)

  如果所有候选都以 <EOS> 结束,停止

步骤 T+1: 输出
  从 candidates 中选择分数最高的序列

详细示例 (k=2):
═══════════════

任务: "I love you" → ?

时间步 t=1:
───────────

当前候选: [(<SOS>,)]

扩展: 计算 P(w | <SOS>, c) 对所有 w ∈ V

假设前5个概率:
  "我":   0.6  log=-0.51
  "你":   0.15 log=-1.90
  "他":   0.10 log=-2.30
  "爱":   0.08 log=-2.53
  "她":   0.05 log=-3.00

选择 top-k=2:
  候选1: (<SOS>, 我)   score=-0.51
  候选2: (<SOS>, 你)   score=-1.90

时间步 t=2:
───────────

当前候选:
  候选1: (<SOS>, 我)   score=-0.51
  候选2: (<SOS>, 你)   score=-1.90

扩展候选1: (<SOS>, 我) + ?
  P(w | 我, c):
    "爱":   0.8  log=-0.22  total=-0.51+(-0.22)=-0.73
    "喜欢": 0.1  log=-2.30  total=-0.51+(-2.30)=-2.81
    "恨":   0.05 log=-3.00  total=-0.51+(-3.00)=-3.51
    "们":   0.03 log=-3.51  total=-0.51+(-3.51)=-4.02
    ...

  新候选:
    (<SOS>, 我, 爱)    score=-0.73
    (<SOS>, 我, 喜欢)  score=-2.81

扩展候选2: (<SOS>, 你) + ?
  P(w | 你, c):
    "好":   0.5  log=-0.69  total=-1.90+(-0.69)=-2.59
    "在":   0.3  log=-1.20  total=-1.90+(-1.20)=-3.10
    "是":   0.1  log=-2.30  total=-1.90+(-2.30)=-4.20
    ...

  新候选:
    (<SOS>, 你, 好)  score=-2.59
    (<SOS>, 你, 在)  score=-3.10

所有新候选 (4个):
  (<SOS>, 我, 爱)    score=-0.73  ← 第1
  (<SOS>, 你, 好)    score=-2.59  ← 第2
  (<SOS>, 我, 喜欢)  score=-2.81
  (<SOS>, 你, 在)    score=-3.10

选择 top-k=2:
  候选1: (<SOS>, 我, 爱)  score=-0.73
  候选2: (<SOS>, 你, 好)  score=-2.59

时间步 t=3:
───────────

当前候选:
  候选1: (<SOS>, 我, 爱)  score=-0.73
  候选2: (<SOS>, 你, 好)  score=-2.59

扩展候选1: (<SOS>, 我, 爱) + ?
  P(w | 我, 爱, c):
    "你":   0.7  log=-0.36  total=-0.73+(-0.36)=-1.09
    "他":   0.2  log=-1.61  total=-0.73+(-1.61)=-2.34
    "她":   0.05 log=-3.00  total=-0.73+(-3.00)=-3.73
    ...

  新候选:
    (<SOS>, 我, 爱, 你)  score=-1.09
    (<SOS>, 我, 爱, 他)  score=-2.34

扩展候选2: (<SOS>, 你, 好) + ?
  P(w | 你, 好, c):
    "吗":   0.6  log=-0.51  total=-2.59+(-0.51)=-3.10
    "啊":   0.3  log=-1.20  total=-2.59+(-1.20)=-3.79
    ...

  新候选:
    (<SOS>, 你, 好, 吗)  score=-3.10
    (<SOS>, 你, 好, 啊)  score=-3.79

所有新候选 (4个):
  (<SOS>, 我, 爱, 你)  score=-1.09  ← 第1
  (<SOS>, 我, 爱, 他)  score=-2.34  ← 第2
  (<SOS>, 你, 好, 吗)  score=-3.10
  (<SOS>, 你, 好, 啊)  score=-3.79

选择 top-k=2:
  候选1: (<SOS>, 我, 爱, 你)  score=-1.09
  候选2: (<SOS>, 我, 爱, 他)  score=-2.34

时间步 t=4:
───────────

扩展候选1: (<SOS>, 我, 爱, 你) + ?
  P(w | 我, 爱, 你, c):
    <EOS>: 0.9  log=-0.11  total=-1.09+(-0.11)=-1.20

  新候选:
    (<SOS>, 我, 爱, 你, <EOS>)  score=-1.20  ← 完成!

扩展候选2: (<SOS>, 我, 爱, 他) + ?
  P(w | 我, 爱, 他, c):
    <EOS>: 0.7  log=-0.36  total=-2.34+(-0.36)=-2.70

  新候选:
    (<SOS>, 我, 爱, 他, <EOS>)  score=-2.70  ← 完成!

两个候选都已结束,停止搜索

最终结果:
────────

候选序列:
  1. "我 爱 你"  score=-1.20  ← 最优!
  2. "我 爱 他"  score=-2.70

输出: "我 爱 你"

对比贪心搜索:
  束搜索找到了更好的全局解!
```

### 完整实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from typing import List, Tuple

class BeamSearch:
    """束搜索解码器"""

    def __init__(self, model, beam_size=3, max_len=50,
                 sos_id=1, eos_id=2):
        """
        参数:
            model: Seq2Seq 模型
            beam_size: 束宽
            max_len: 最大生成长度
            sos_id: 开始符号 ID
            eos_id: 结束符号 ID
        """
        self.model = model
        self.beam_size = beam_size
        self.max_len = max_len
        self.sos_id = sos_id
        self.eos_id = eos_id

    def search(self, encoder_output):
        """
        束搜索解码

        参数:
            encoder_output: 编码器输出 [batch_size=1, seq_len, hidden_size]

        返回:
            best_sequence: 最佳序列 [seq_len]
            best_score: 最佳分数 (对数概率)
        """
        batch_size = encoder_output.size(0)
        assert batch_size == 1, "束搜索当前只支持 batch_size=1"

        # 初始化
        # candidates: List[(sequence, score, hidden)]
        # sequence: List[int] - 词 ID 序列
        # score: float - 累积对数概率
        # hidden: tensor - 解码器隐藏状态

        init_hidden = self.model.decoder.init_hidden(encoder_output)
        candidates = [
            ([self.sos_id], 0.0, init_hidden)
        ]

        finished = []  # 已完成的序列

        for t in range(self.max_len):
            all_candidates = []

            # 扩展每个候选
            for seq, score, hidden in candidates:
                # 如果已经结束,不再扩展
                if seq[-1] == self.eos_id:
                    finished.append((seq, score))
                    continue

                # 获取最后一个词
                last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
                # last_word: [batch=1, seq_len=1]

                # 解码一步
                output, new_hidden = self.model.decoder(
                    last_word, hidden, encoder_output
                )
                # output: [batch=1, seq_len=1, vocab_size]

                # 计算对数概率
                log_probs = F.log_softmax(output.squeeze(0).squeeze(0), dim=0)
                # log_probs: [vocab_size]

                # 获取前 beam_size 个词
                top_log_probs, top_indices = torch.topk(
                    log_probs, self.beam_size
                )

                # 创建新候选
                for log_prob, word_id in zip(top_log_probs, top_indices):
                    new_seq = seq + [word_id.item()]
                    new_score = score + log_prob.item()
                    all_candidates.append(
                        (new_seq, new_score, new_hidden)
                    )

            # 如果没有新候选(所有序列都已结束)
            if not all_candidates:
                break

            # 选择前 beam_size 个候选
            # 按分数排序(降序)
            all_candidates.sort(key=lambda x: x[1], reverse=True)
            candidates = all_candidates[:self.beam_size]

            # 早停: 如果已有足够的完成序列
            if len(finished) >= self.beam_size:
                break

        # 将未完成的候选也加入
        finished.extend(candidates)

        # 选择最佳序列
        finished.sort(key=lambda x: x[1], reverse=True)
        best_seq, best_score = finished[0]

        return best_seq, best_score


# ═══════════════════════════════════════════════════════
# 使用示例
# ═══════════════════════════════════════════════════════

class Seq2SeqModel(nn.Module):
    """简化的 Seq2Seq 模型"""
    def __init__(self, vocab_size, embed_size, hidden_size):
        super().__init__()
        self.encoder = Encoder(vocab_size, embed_size, hidden_size)
        self.decoder = Decoder(vocab_size, embed_size, hidden_size)

    def forward(self, src, tgt):
        encoder_output, hidden = self.encoder(src)
        decoder_output, _ = self.decoder(tgt, hidden, encoder_output)
        return decoder_output


# 创建模型
model = Seq2SeqModel(vocab_size=10000, embed_size=256, hidden_size=512)

# 创建束搜索解码器
beam_search = BeamSearch(
    model,
    beam_size=5,
    max_len=50,
    sos_id=1,
    eos_id=2
)

# 编码输入
src = torch.LongTensor([[3, 145, 67, 2]])  # "I love you <EOS>"
encoder_output, _ = model.encoder(src)

# 束搜索解码
best_seq, best_score = beam_search.search(encoder_output)

print(f"最佳序列: {best_seq}")
print(f"对数概率: {best_score:.4f}")
print(f"概率: {torch.exp(torch.tensor(best_score)):.4f}")
```

## 🔧 束搜索优化

### 优化 1: 长度归一化 (Length Normalization)

```
问题:
════

束搜索默认最大化:
  score = Σᵢ log P(yᵢ | x, y<ᵢ)

问题:
  对数概率总是负数
  序列越长,累加越多负数
  → 倾向于选择短序列!

示例:
────

序列1: "我 爱 你"
  score = -0.5 + (-0.2) + (-0.1) = -0.8

序列2: "我 非常 爱 你"
  score = -0.5 + (-0.3) + (-0.2) + (-0.15) = -1.15

序列1 > 序列2 (因为更短)

但平均来看:
  序列1: -0.8 / 3 = -0.267
  序列2: -1.15 / 4 = -0.288

序列1 仍然更好,但差距缩小

解决方案:
════════

长度归一化:
  score_normalized = score / length^α

其中:
  α ∈ [0, 1] 是超参数
  α = 0: 不归一化
  α = 1: 完全归一化 (平均对数概率)
  α = 0.6-0.7: 实践中常用

Google's NMT (Wu et al., 2016) 使用:
  score_normalized = score / ((5 + length) / 6)^α

代码实现:
────────

```python
def length_penalty(length, alpha=0.6):
    """长度惩罚"""
    return ((5 + length) / 6) ** alpha

def beam_search_with_length_norm(model, encoder_output,
                                 beam_size=5, alpha=0.6):
    """带长度归一化的束搜索"""

    for t in range(max_len):
        for seq, score, hidden in candidates:
            # ... (扩展候选)

            # 计算归一化分数
            new_score_normalized = new_score / length_penalty(len(new_seq), alpha)

            all_candidates.append(
                (new_seq, new_score, new_score_normalized, new_hidden)
            )

        # 按归一化分数排序
        all_candidates.sort(key=lambda x: x[2], reverse=True)
        candidates = all_candidates[:beam_size]

    # ...
```

效果:
────

不归一化:
  "我爱你" (短)  score=-0.8
  "我非常爱你" (长) score=-1.15
  → 选择短序列

归一化 (α=0.6):
  "我爱你"     normalized=-0.8 / 3^0.6 = -0.42
  "我非常爱你" normalized=-1.15 / 4^0.6 = -0.48
  → 仍然选择短序列,但差距更合理

如果长序列真的更好:
  "我非常非常爱你" score=-1.2
  normalized=-1.2 / 5^0.6 = -0.40
  → 可能被选中!
```

### 优化 2: 覆盖惩罚 (Coverage Penalty)

```
问题:
════

束搜索可能生成重复的短语

示例:
  "I love love love you"
  "我 爱 爱 爱 你"

原因:
  某些词的概率可能一直很高
  模型可能"卡住"在某个词上

解决方案:
════════

覆盖惩罚 (Coverage Penalty):
  惩罚重复关注源序列的同一部分

假设有注意力权重 attention[t, s]:
  t: 目标序列的第 t 个词
  s: 源序列的第 s 个词

覆盖向量:
  coverage[s] = Σₜ attention[t, s]

如果某个位置被过度关注 (coverage > 1)
给予惩罚

覆盖惩罚:
  penalty = λ · Σₛ min(coverage[s], 1)

总分数:
  score_final = score - penalty

代码实现:
────────

```python
def coverage_penalty(attention_weights, beta=0.5):
    """
    覆盖惩罚

    参数:
        attention_weights: [target_len, source_len]
        beta: 惩罚系数

    返回:
        penalty: 标量
    """
    # 计算覆盖向量
    coverage = attention_weights.sum(dim=0)  # [source_len]

    # 惩罚过度覆盖的位置
    penalty = beta * torch.sum(torch.log(coverage + 1e-10))

    return penalty.item()

# 在束搜索中使用
for seq, score, hidden, attention_history in candidates:
    # ... (生成新词)

    # 计算覆盖惩罚
    penalty = coverage_penalty(attention_history, beta=0.5)

    # 调整分数
    new_score = score + log_prob - penalty
```

### 优化 3: 多样性促进 (Diversity Promotion)

```
问题:
════

束搜索的多个候选可能非常相似

示例 (beam_size=3):
  候选1: "我 爱 你"
  候选2: "我 非常 爱 你"
  候选3: "我 真的 爱 你"

都是 "我...爱你" 的变体
缺乏多样性

解决方案:
════════

方法1: 多样性束搜索 (Diverse Beam Search)
  将束分成多个组
  每组独立搜索
  组间促进多样性

方法2: 随机束搜索 (Stochastic Beam Search)
  不总是选择 top-k
  而是从 top-2k 中随机采样 k 个

方法3: 温度采样 (Temperature Sampling)
  调整概率分布的锐度
  P'(w) = P(w)^(1/T) / Σ P(w)^(1/T)
  T > 1: 更平滑 (更多样)
  T < 1: 更锐利 (更确定)

代码实现 (温度采样):
──────────────────

```python
def temperature_sampling(logits, temperature=1.0):
    """
    温度采样

    参数:
        logits: [vocab_size]
        temperature: 温度系数

    返回:
        sampled_id: 采样的词 ID
    """
    # 应用温度
    logits = logits / temperature

    # Softmax
    probs = F.softmax(logits, dim=0)

    # 采样
    sampled_id = torch.multinomial(probs, 1)

    return sampled_id.item()

# 在束搜索中使用
for t in range(max_len):
    for seq, score, hidden in candidates:
        # 解码
        output, new_hidden = decoder(...)
        logits = output.squeeze()

        # 温度采样 (而非 argmax)
        word_id = temperature_sampling(logits, temperature=0.8)
        log_prob = F.log_softmax(logits, dim=0)[word_id]

        new_seq = seq + [word_id]
        new_score = score + log_prob.item()
```

### 优化 4: 剪枝策略 (Pruning Strategies)

```
问题:
════

束搜索需要维护 k 个候选
每步需要计算 k × V 个扩展
计算量仍然较大

解决方案:
════════

早期剪枝:
  如果某个候选的分数远低于最佳候选
  不再扩展

阈值剪枝:
  score_threshold = best_score - margin
  只保留 score > score_threshold 的候选

代码实现:
────────

```python
def beam_search_with_pruning(model, encoder_output,
                            beam_size=5, margin=3.0):
    """带剪枝的束搜索"""
    candidates = [([sos_id], 0.0, init_hidden)]

    for t in range(max_len):
        all_candidates = []

        # 找到当前最佳分数
        best_score = max(score for _, score, _ in candidates)
        threshold = best_score - margin

        for seq, score, hidden in candidates:
            # 剪枝: 分数过低的候选
            if score < threshold:
                continue  # 不扩展

            # 扩展候选
            # ...

        # 选择前 beam_size 个
        all_candidates.sort(key=lambda x: x[1], reverse=True)
        candidates = all_candidates[:beam_size]

    return candidates[0]
```

## 📊 复杂度分析

```
贪心搜索:
════════

时间复杂度:
  每步: O(V)  (计算所有词的概率)
  总共: O(T × V)

空间复杂度:
  O(1)  (只保留当前候选)

束搜索:
══════

时间复杂度:
  每步: O(k × V)  (扩展 k 个候选,每个考虑 V 个词)
  选择: O(k × V × log(k × V))  (排序)
  总共: O(T × k × V × log(k × V))

空间复杂度:
  O(k × T)  (保留 k 个长度为 T 的候选)

实践优化:
════════

不需要计算所有 V 个词:
  只计算前 top-p 个最可能的词
  top-p = 100-1000 (远小于 V=10,000-50,000)

优化后:
  时间: O(T × k × p × log(k × p))
  p << V → 显著加速

示例:
  V = 50,000
  k = 5
  p = 500
  T = 30

  原始: 30 × 5 × 50,000 = 7,500,000 次计算
  优化: 30 × 5 × 500 = 75,000 次计算
  加速 100 倍！
```

## 🤔 常见问题

```
Q1: 束搜索一定比贪心好吗？
A1: 不一定
    - 大多数情况: 束搜索 > 贪心
    - 但有时贪心更快且足够好
    - 实时系统可能优先贪心

Q2: beam_size 越大越好吗？
A2: 不是
    - k ↑ → 质量 ↑ 但收益递减
    - k ↑ → 计算 ↑ 线性增长
    - 实践: k=5-10 通常最佳

Q3: 为什么不用最大化 P(y|x) 而用 log P?
A3: 数值稳定性
    - P(y|x) = ∏ P(yᵢ|...) → 连乘很小的数 → 下溢
    - log P(y|x) = Σ log P(yᵢ|...) → 求和 → 稳定

Q4: 束搜索能保证全局最优吗？
A4: ❌ 不能
    - 仍然是启发式搜索
    - 但比贪心更接近最优
    - 实践中效果很好

Q5: 如何处理不同长度的候选？
A5: 长度归一化
    - score / length^α
    - 或使用 Google 的公式
```
