## 📖 理论学习

### 1. 什么是 Few-Shot Prompting？

#### 1.1 核心定义

**定义**:
Few-Shot Prompting 是一种提示技术，通过在提示中提供少量示例（通常 2-10 个）来帮助模型理解任务要求和期望的输出格式。

**本质特征**:
```
Few-Shot = 任务指令 + 几个高质量示例 + 待完成任务

工作机制:
示例提供 → 模式识别 → 类比推理 → 新任务执行
```

**关键要素**:
```
示例 = 输入示例 + 输出示例
Few-Shot Prompt = 任务描述 + N个示例 + 新输入
```

### 2. Few-Shot 的工作机制

#### 2.1 模式激活机制

**激活流程**:
```python
# 伪代码示例
def few_shot_processing(prompt, examples, new_input):
    # 1. 整合示例信息
    context = prompt + examples

    # 2. 激活相关模式
    activated_patterns = model.activate_patterns(context)

    # 3. 分析输入特征
    input_features = model.analyze_features(new_input)

    # 4. 匹配模式
    matched_patterns = model.match_patterns(
        input_features, activated_patterns
    )

    # 5. 生成输出
    output = model.generate_output(
        new_input, matched_patterns
    )

    return output
```

```

Level 1: 表面模式
```

### 3. Few-Shot 设计原则

#### 3.1 示例质量原则

**高质量示例标准**:
```yaml
标准1: 准确性 (Accuracy)
- 内容准确无误
- 逻辑清晰合理
- 事实真实可靠
- 推理正确有效

标准2: 代表性 (Representativeness)
- 覆盖典型情况
- 代表常见类型
- 体现任务范围
- 平衡各种情况

标准3: 一致性 (Consistency)
- 格式统一规范
- 风格保持一致
- 结构清晰稳定
- 标准明确统一

标准4: 可读性 (Readability)
- 语言简洁明了
- 表达自然流畅
- 逻辑易于理解
- 重点突出清晰

示例质量评估:
优秀 (9-10分): 完全符合所有标准
良好 (7-8分): 基本符合，细节需改进
合格 (5-6分): 符合基本要求
不合格 (<5分): 不符合基本要求
```

**示例选择策略**:
```yaml
策略1: 多样性平衡
平衡维度:
- 输入多样性: 不同类型输入
- 输出多样性: 不同正确输出
- 难度多样性: 简单到复杂
- 场景多样性: 不同应用场景

具体操作:
- 包含2-3种典型输入类型
- 每种类型1-2个示例
- 确保输出质量稳定
- 覆盖常见边界情况

策略2: 难度递进
难度层次:
- Level 1: 简单直接 (70%)
- Level 2: 中等复杂 (25%)
- Level 3: 复杂困难 (5%)

设计原则:
- 先简单后复杂
- 逐步增加挑战
- 保持整体连贯
- 确保可理解性

策略3: 负面对比
负面对比价值:
- 突出正确做法
- 避免常见错误
- 提供判断标准
- 增强理解深度

设计方法:
- 包含1个负面示例
- 明确标注问题
- 解释改进方向
- 引导正确理解
```

#### 3.2 示例组织原则

**示例数量选择**:
```yaml
数量选择理论:
理论分析:
- 1个示例: 基础任务，清晰边界
- 2-3个示例: 通用任务，模式识别
- 4-5个示例: 复杂任务，多样性
- 6-10个示例: 非常复杂，全面覆盖

实际选择指南:
- 简单任务: 1-2个示例
- 中等任务: 2-4个示例
- 复杂任务: 4-6个示例
- 专业任务: 5-10个示例

最佳实践:
推荐数量: 2-5个
平衡考虑: 效果 vs 成本
调整原则: 根据效果迭代优化
```

**示例排列顺序**:
```yaml
顺序策略1: 简单到复杂
排列逻辑:
1. 最简单的示例 (建立基础)
2. 中等复杂的示例 (逐步递进)
3. 最复杂的示例 (挑战上限)

适用场景:
- 教学型任务
- 逐步学习任务
- 技能发展任务

顺序策略2: 典型到边缘
排列逻辑:
1. 最典型的示例 (核心概念)
2. 常见变体 (扩展理解)
3. 边缘案例 (边界理解)

适用场景:
- 模式识别任务
- 分类任务
- 规范任务

顺序策略3: 对比交替
排列逻辑:
1. 正面示例 (正确做法)
2. 负面示例 (错误示例)
3. 正面示例 (强化理解)

适用场景:
- 质量要求高
- 容易混淆的任务
- 错误风险大

最佳实践:
- 从简单到复杂最常用
- 根据任务特点调整
- 保持逻辑连贯性
- 考虑理解负担
```

```python
def bubble_sort(arr):
```
```python
    """
    使用冒泡排序算法对数组进行升序排序
    Args:
        arr: 待排序的数组
    Returns:
        排序后的数组
    """
    n = len(arr)  # 获取数组长度
    # 外层循环控制排序轮数
    for i in range(n):
        # 内层循环进行相邻元素比较和交换
        for j in range(0, n-i-1):
            # 如果前一个元素大于后一个元素，交换它们
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
    return arr  # 返回排序后的数组
```

```yaml
□ 示例逻辑清晰合理
□ 示例格式统一规范
□ 示例风格保持一致

原则2: 数量适度平衡
要点:
- 2-5个最佳: 多数任务2-5个示例足够
- 避免过多: 过多示例增加成本和混乱
- 任务特异化: 根据任务复杂度调整数量
- 效果导向: 以效果为准，不追求数量

选择指南:
简单任务: 1-2个示例
中等任务: 2-4个示例
复杂任务: 4-6个示例
专业任务: 5-10个示例

原则3: 组织逻辑清晰
要点:
- 顺序合理: 从简单到复杂或对比排列
- 过渡自然: 示例间逻辑连贯
- 结构统一: 所有示例使用相同结构
- 格式一致: 标签、标记、格式统一

组织策略:
渐进式: 简单→中等→复杂
对比式: 正确→错误→正确
主题式: 主题1→主题2→主题3
时间式: 过去→现在→未来

原则4: 持续优化改进
要点:
- 效果监控: 持续跟踪输出质量
- 反馈收集: 收集用户和系统反馈
- 迭代优化: 根据效果调整示例
```
