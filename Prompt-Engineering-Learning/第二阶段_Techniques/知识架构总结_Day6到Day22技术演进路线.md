## 核心对比：ReAct vs Graph Prompting 🔍

### 最本质的区别

```python
核心区别 = {
    # ========== 数据结构 ==========
    "数据结构": {
        "ReAct": "数组/列表(线性)",
        "Graph Prompting": "图(节点+边)"
    },

    # ========== 推理范式 ==========
    "推理范式": {
        "ReAct": "顺序推理(一条线)",
        "Graph Prompting": "网络推理(多条路径)"
    },

    # ========== ToT和Self-Consistency的使用方式 ==========
    "ToT/Self-Consistency使用": {
        "ReAct": {
            "位置": "第二层推理计划层",
            "方式": "临时构建树状/多路径结构",
            "持久化": "❌ 不持久化!最终只选一个thought,树被丢弃",
            "存储": "history只保存线性主流程的最终选择"
        },
        "Graph Prompting": {
            "位置": "第二阶段多路径生成层",
            "方式": "树状搜索所有可能路径",
            "持久化": "✅ 持久化!所有路径都保存在图中",
            "存储": "graph.nodes和graph.edges保存所有路径和节点"
        }
    },

    # ========== 流程对比 ==========
    "流程对比": {
        "ReAct": "线性主流程 → 第二层临时树状探索 → 选一个thought → 继续线性",
        "Graph Prompting": "构建图 → 生成所有路径(持久化) → 评分 → 选最优路径 → 推理"
    },

    # ========== LLM调用次数 ==========
    "LLM调用": {
        "ReAct": "2N+2次(N轮循环)",
        "Graph Prompting": "视路径数而定,通常更多"
    },

    # ========== 适用场景 ==========
    "适用场景": {
        "ReAct": "顺序依赖任务,简单查询,实时交互,工具调用密集",
        "Graph Prompting": "关系密集型问题,多路径推理,知识图谱查询,因果推理,优化路径"
    }
}
```

### 技术融合的核心区别

```
ReAct (临时树/多路径):
━━━━━━━━━━━━━━━━━━━━━━━━
第二层推理计划层:
  ├─ 使用ToT树状探索
  ├─ 使用Self-Consistency多路径
  ├─ 临时构建,不持久化
  └─ 选出一个thought → 树被丢弃

history = [
  {thought: "选中的thought", ...},  # 只保存最终选择
  ...
]

━━━━━━━━━━━━━━━━━━━━━━━━

Graph Prompting (持久化图/所有路径):
━━━━━━━━━━━━━━━━━━━━━━━━

第二阶段多路径生成层:
  ├─ 使用ToT树状搜索
  ├─ 使用Self-Consistency并行探索
  ├─ 所有路径持久化保存
  └─ 评分选最优,但所有路径都保留

graph.nodes = {所有实体节点}       # 全部保存!
graph.edges = {所有推理路径的边}   # 全部保存!
all_paths = [路径1, 路径2, ...]   # 全部保存!

━━━━━━━━━━━━━━━━━━━━━━━━

这TM才是本质区别!
```
