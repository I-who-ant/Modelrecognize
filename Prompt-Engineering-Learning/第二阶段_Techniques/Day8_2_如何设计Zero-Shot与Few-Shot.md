## 核心问题回答

**Q**: 如何让模型使用Zero-Shot或Few-Shot？只需要给出对应的提示词吗？
**A**: 不只是提示词！需要完整的设计框架，包括示例选择、格式设计、质量控制等。

### 2.2 Zero-Shot Prompt模板

#### 模板1: 信息提取任务

```
结构:
┌─────────────────────────────────────────┐
│ [角色设定]                              │
│ + [任务描述]                            │
│ + [输入格式]                            │
│ + [输出格式]                            │
│ + [约束条件]                            │
│ + [边界情况]                            │
└─────────────────────────────────────────┘

实际示例:
"你是一个专业的文本分析助手。
请从给定文本中提取公司名称。

输入格式:
文本: [在这里粘贴文本]

输出格式:
只返回公司名称，用逗号分隔。
如果没找到，返回'无'。

约束:
- 只提取公司名，不要包含个人姓名
- 不要包含地名或组织名
- 名称要完整，不要截断

边界情况:
- 文本为空 → 返回'无'
- 没有明确公司 → 返回'无'
- 多个公司 → 全部提取"

测试输入: "苹果公司今天宣布..."
期望输出: "苹果公司"
```

#### 模板2: 分类任务

```
结构:
┌─────────────────────────────────────────┐
│ [背景说明]                              │
│ + [类别定义]                            │
│ + [输入处理]                            │
│ + [输出格式]                            │
│ + [决策规则]                            │
└─────────────────────────────────────────┘

实际示例:
"你是一个文本分类专家。
请将输入文本分类为以下类别:
- 正面: 表达积极情绪或好评
- 负面: 表达消极情绪或差评
- 中性: 不带情绪或客观描述

处理规则:
- 输入: 一段文本
- 输出: 只返回分类结果
- 不要解释，不要额外内容

注意:
- 重点关注情绪色彩，不是事实对错
- 讽刺语句按表面意思判断
- 数字评价: 5星=正面, 3星=中性, 1星=负面"

测试输入: "这部电影太棒了！"
期望输出: "正面"
```

#### 模板3: 格式转换任务

```
结构:
┌─────────────────────────────────────────┐
│ [转换目标]                              │
│ + [输入描述]                            │
│ + [输出规范]                            │
│ + [转换规则]                            │
│ + [质量检查]                            │
└─────────────────────────────────────────┘

实际示例:
"你是一个数据格式转换专家。
请将JSON格式转换为CSV格式。

输入: 标准JSON对象，包含key-value对
输出: CSV格式，第一行是列名

转换规则:
1. JSON的key成为CSV的列名
2. JSON的value成为CSV的行值
3. 嵌套对象转换为字符串
4. 数组转换为分隔的字符串

输出规范:
- 只返回CSV内容，不要解释
- 用逗号分隔
- 用双引号包围包含逗号的值
- 保持原始数据类型"

JSON输入: {"name":"张三","age":25,"skills":["Python","SQL"]}
期望CSV输出: name,age,skills
"张三",25,"Python,SQL"
```

### 2.3 Zero-Shot 设计要点

```
成功要素:
┌─────────────────────────────────────────┐
│ 1. 指令清晰度                           │
│    ├─ 具体动词 (提取/转换/分类)         │
│    ├─ 明确目标 (什么→什么)              │
│    └─ 避免模糊 (最好/正常等)            │
│                                          │
│ 2. 格式约束                             │
│    ├─ 输出格式 (JSON/CSV/列表)          │
│    ├─ 内容限制 (只/不要)                │
│    └─ 长度控制 (字数/行数)              │
│                                          │
│ 3. 边界处理                             │
│    ├─ 异常情况 (没有/空/错误)           │
│    ├─ 默认值 (返回什么)                 │
│    └─ 错误提示 (如何表示)               │
│                                          │
│ 4. 质量保证                             │
│    ├─ 检查规则 (如何验证)               │
│    ├─ 格式验证 (是否符合要求)           │
│    └─ 内容验证 (是否合理)               │
└─────────────────────────────────────────┘
```

## 4. 实战设计案例

### 案例1: 客户反馈分类

#### Zero-Shot方案

```
Prompt:
"你是一个客户反馈分析专家。
请将客户反馈分类为以下类别:
- 投诉: 表达不满、问题、抱怨
- 建议: 提出改进意见、想法
- 表扬: 表达满意、赞赏、感谢
- 询问: 提出问题、寻求帮助

规则:
- 只返回类别名称
- 不要解释
- 一个反馈只属于一个类别

边界情况:
- 多个情绪 → 选择主要情绪
- 模糊表达 → 选择最可能类别"

测试: "这个功能很好用，谢谢！"
期望: "表扬"
```

#### Few-Shot方案

```

"将客户反馈分类:

反馈: "产品坏了，我要投诉！"
类别: "投诉"

示例2:
反馈: "希望增加夜间模式功能"
类别: "建议"

示例3:
反馈: "谢谢你们的服务！"
类别: "表扬"

反馈: "怎么退货？"
类别: "询问"
```

## 6. 常见错误与避免

### 6.1 Zero-Shot常见错误

```
错误1: 指令模糊
❌ 错误示例:
"帮我处理这个文本"

✅ 正确示例:
"提取文本中的公司名称，用逗号分隔，返回列表"

错误2: 缺少格式约束
❌ 错误示例:
"分类这个文本"

✅ 正确示例:
"分类文本为正面/负面/中性，只返回类别名称"

错误3: 忽略边界情况
❌ 错误示例:
"提取关键词"

✅ 正确示例:
"提取关键词。如果没有关键词，返回'无'"

错误4: 缺少示例格式
❌ 错误示例:
"转换为JSON"

✅ 正确示例:
"转换为JSON格式，示例: 输入'A:1' 输出{'key':'A','value':1}"
```

### 6.2 Few-Shot常见错误

```
错误1: 示例不一致
❌ 错误示例:
示例1: "输入:X 输出:Y"
示例2: "X -> Y"
示例3: "Input: X Output: Y"

✅ 正确示例:
示例1: "输入:X 输出:Y"
示例2: "输入:X 输出:Y"
示例3: "输入:X 输出:Y"

错误2: 示例重复
❌ 错误示例:
示例1: "A → B"
示例2: "A → B" (相同)

✅ 正确示例:
示例1: "A → B"
示例2: "C → D"
示例3: "E → F"

错误3: 示例质量低
❌ 错误示例:
复杂示例、逻辑混乱

✅ 正确示例:
简短、清晰、正确

错误4: 示例太少或太多
❌ 错误示例:
1个示例(激活弱) 或 10个示例(冗余)

✅ 正确示例:
2-5个精选示例
```

## 7. 总结

### 7.1 设计流程对比

```
Zero-Shot vs Few-Shot 设计流程:
┌─────────────────────────────────────────┐
│ Zero-Shot:                             │
│ ├─ 明确任务 → 设计指令 → 格式约束        │
│ ├─ 边界处理 → 测试迭代                  │
│ └─ 关键: 指令质量                       │
│                                          │
│ Few-Shot:                              │
│ ├─ 任务分析 → 示例设计 → 模式提炼        │
│ ├─ 质量优化 → 泛化验证                  │
│ └─ 关键: 示例质量                       │
└─────────────────────────────────────────┘
```

### 7.2 核心设计原则

```
成功设计要点:
┌─────────────────────────────────────────┐
│ Zero-Shot:                             │
│ ├─ 指令清晰具体                         │
│ ├─ 格式约束明确                         │
│ ├─ 边界情况覆盖                         │
│ └─ 测试迭代优化                         │
│                                          │
│ Few-Shot:                              │
│ ├─ 示例精选优质                         │
│ ├─ 格式严格统一                         │
│ ├─ 模式清晰激活                         │
│ └─ 泛化能力验证                         │
└─────────────────────────────────────────┘
```

### 7.3 终极建议

```
实战建议:
┌─────────────────────────────────────────┐
│ 1. 先用Zero-Shot探索                     │
│    ├─ 快速验证可行性                     │
│    ├─ 了解任务难点                       │
│    └─ 收集测试案例                       │
│                                          │
│ 2. 根据需要转向Few-Shot                  │
│    ├─ 质量要求高                         │
│    ├─ 稳定性重要                         │
│    └─ 格式严格                          │
│                                          │
│ 3. 持续优化改进                          │
│    ├─ 收集反馈                           │
│    ├─ 分析错误                           │
│    └─ 迭代设计                           │
└─────────────────────────────────────────┘
```
