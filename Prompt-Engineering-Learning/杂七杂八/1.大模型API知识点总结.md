## 🎯 核心概念介绍

### 什么是大模型API？

大模型API是基于RESTful架构或WebSocket协议的服务接口，允许开发者通过HTTP请求调用预训练的大型语言模型，无需自行部署和训练模型。

```
API调用模式:
┌─────────────────────────────────────────┐
│ 开发者应用                               │
│       ↓ HTTP请求                         │
│ 大模型API服务                            │
│       ↓ 模型推理                         │
│ 预训练大模型                             │
│       ↓ 返回结果                         │
│ API服务                                  │
│       ↓ HTTP响应                         │
│ 开发者应用                               │
└─────────────────────────────────────────┘
```

## 📚 专业术语详解

### 1. Endpoints (端点)

**定义**: API服务器上用于接收请求的特定URL地址

```
Endpoints结构:
┌─────────────────────────────────────────┐
│ 基础URL + 路径 = 完整端点                 │
│                                          │
│ OpenAI示例:                             │
│ ├─ 基础URL: https://api.openai.com      │
│ ├─ Chat端点: /v1/chat/completions       │
│ └─ 完整端点: https://api.openai.com     │
│              /v1/chat/completions       │
│                                          │
│ DeepSeek示例:                           │
│ ├─ 基础URL: https://api.deepseek.com    │
│ ├─ Chat端点: /chat/completions          │
│ └─ 完整端点: https://api.deepseek.com   │
│              /chat/completions          │
└─────────────────────────────────────────┘
```

**常见端点类型**:
```
Chat Completions: /v1/chat/completions
├─ 功能: 对话生成
├─ 输入: 消息列表
└─ 输出: 模型回复

Embeddings: /v1/embeddings
├─ 功能: 文本向量化
├─ 输入: 文本内容
└─ 输出: 向量表示

Images: /v1/images/generations
├─ 功能: 图像生成
├─ 输入: 文本描述
└─ 输出: 图像URL

Files: /v1/files
├─ 功能: 文件管理
├─ 上传/下载/删除
└─ 用于微调数据
```

### 2. Token (令牌)

**定义**: 模型处理的最小文本单位，可以是词、词片段或字符

```
Token化过程:
┌─────────────────────────────────────────┐
│ 原始文本: "你好，世界！"                  │
│                                          │
│ 分词结果:                                │
│ ├─ "你好" → Token 1                      │
│ ├─ "，" → Token 2                        │
│ ├─ "世界" → Token 3                      │
│ ├─ "！" → Token 4                        │
│ └─ 总计: 4个Token                        │
│                                          │
│ 英文示例:                                │
│ "Hello world!"                           │
│ ├─ "Hello" → Token 1                     │
│ ├─ " world" → Token 2                    │
│ └─ "!" → Token 3                         │
└─────────────────────────────────────────┘
```

**Token计算规则**:
```
估算方法1: 1 Token ≈ 0.75 个英文单词
示例: 1000个英文单词 ≈ 1333个Token

估算方法2: 1 Token ≈ 4个字符（中文）
示例: "你好世界" (4字符) ≈ 1个Token

估算方法3: 1 Token ≈ 0.5个中文词
示例: "你好" (1个中文词) ≈ 2个Token

实际计算:
├─ 输入Prompt: 100 Token
├─ 生成回答: 200 Token
└─ 总计: 300 Token
```

**Token限制**:
```
不同模型的Token限制:
┌─────────────────────────────────────────┐
│ 模型              │ 输入+输出限制        │
├─────────────────────────────────────────┤
│ GPT-3.5-turbo     │ 16K / 32K Token      │
│ GPT-4             │ 8K / 32K / 128K Token│
│ Claude-3-haiku    │ 200K Token            │
│ DeepSeek-V3       │ 128K Token            │
│ Gemini-pro        │ 1M Token (实验)      │
└─────────────────────────────────────────┘

注意事项:
├─ 超过限制会报错
├─ 建议预留10%安全边界
└─ 超长输入会被截断
```

### 3. Prompt (提示词)

**定义**: 输入给模型的指令和上下文，用于指导模型生成特定类型的输出

```
Prompt结构:
┌─────────────────────────────────────────┐
│ Prompt = 角色定义 + 任务描述 + 示例 + 输入│
│                                          │
│ 基础Prompt:                              │
│ "你是一个专业的翻译助手。请将英文翻译成   │
│ 中文：Hello world"                       │
│                                          │
│ 结构化Prompt:                            │
│ ├─ 角色: "你是一个专业的翻译助手"        │
│ ├─ 任务: "请将英文翻译成中文"            │
│ ├─ 示例: "翻译示例..."                   │
│ └─ 输入: "Hello world"                  │
└─────────────────────────────────────────┘
```

**Prompt类型**:
```
System Prompt (系统提示):
├─ 定义: 最高级别的全局指令
├─ 作用: 设置AI助手的行为和角色
├─ 位置: 消息列表第一个
└─ 示例: "你是一个有用的AI助手"

User Prompt (用户提示):
├─ 定义: 用户发送的具体请求
├─ 作用: 表达用户的具体需求
├─ 位置: 消息列表中的用户消息
└─ 示例: "请帮我写一封信"

Assistant Prompt (助手提示):
├─ 定义: 模型生成的回复
├─ 作用: 对话历史和上下文
├─ 位置: 消息列表中的助手消息
└─ 示例: "我很乐意帮助您..."
```

### 优化技巧

#### 1. 角色设定
```
基础角色:

详细角色:
```

```
Few-shot示例:
"翻译以下句子：

例2: Good morning → 早上好
现在翻译: How are you?"

Zero-shot对比:

效果对比:
├─ Few-shot: 准确率提升20%
├─ 提供明确的格式指导
└─ 减少歧义解释
```

#### 3. 链式思考（CoT）
```
直接提问:
"答案: 15 + 27 = ?"

CoT提问:
"请逐步推理计算：15 + 27 = ?
让我们一步一步地思考："

效果对比:
├─ 直接提问: 42 (错误)
├─ CoT提问: 15 + 27 = 42 (正确)
└─ 推理过程提升准确率
```

#### 4. 约束条件
```
无约束:
"写一首诗"

有约束:

- 至少出现2个颜色词

输出质量:
├─ 无约束: 质量参差不齐
├─ 有约束: 符合预期
└─ 约束越具体，输出越稳定
```

#### 5. 分步指导
```
一步到位:
"请帮我分析这个项目并给出改进建议"

分步指导:
"请按照以下步骤分析项目：

└─ 逐步完善
```

### 高级优化技术

#### 1. 自反性提示（Self-Reflective Prompting）
```
机制: 模型先给出答案，然后反思并改进
结构:
├─ 第一轮: 生成初始答案
├─ 第二轮: 反思答案的优缺点
├─ 第三轮: 基于反思改进答案
└─ 重复直到满意

示例:
"请回答：什么是机器学习？
请反思你的答案并改进它
请再次反思并最终完善答案"
```

#### 2. 多角度提示（Multi-Perspective Prompting）
```
机制: 要求模型从多个角度分析问题
角度:
├─ 技术角度
├─ 商业角度
├─ 用户角度
└─ 风险角度

示例:
"请从技术、用户、商业和风险四个角度，
全面分析采用AI技术的可行性"
```

#### 3. 反向提示（Reverse Prompting）
```
机制: 先给出答案，再询问问题的反推技术
用途: 验证理解质量

示例:
"反向验证：基于'机器学习是人工智能的子集'
这个答案，请告诉我相应的问题是什么"
```

## 📡 流式输出（Streaming）

### 流式输出概念

**定义**: 模型在生成内容时，实时将生成的Token逐步返回，而不是等待全部生成完成后一次性返回

```
传统模式 vs 流式模式:
┌─────────────────────────────────────────┐
│ 传统模式 (同步):                         │
│ 请求 → 等待处理 → 一次性返回结果          │
│ 5秒  → 全量输出                          │
│                                          │
│ 流式模式 (异步):                         │
│ 请求 → 实时输出 → 逐步显示               │
│ 1秒  → 逐Token显示                       │
└─────────────────────────────────────────┘
```

### 实现方式

#### 1. Server-Sent Events (SSE)

**协议特点**:
```
SSE特性:
├─ 单向通信（服务器→客户端）
├─ 基于HTTP协议
├─ 使用text/event-stream内容类型
├─ 自动连接重试
└─ 浏览器原生支持

SSE vs WebSocket:
┌─────────────────────────────────────────┐
│ 特性           │ SSE         │ WebSocket│
├─────────────────────────────────────────┤
│ 协议          │ HTTP         │ TCP     │
│ 复杂度        │ 简单         │ 复杂     │
│ 双向通信      │ 否           │ 是       │
│ 浏览器支持    │ 原生         │ 需库支持 │
│ 重连机制      │ 自动         │ 手动     │
│ 适用场景      │ 实时推送     │ 双向交互 │
└─────────────────────────────────────────┘
```

**SSE消息格式**:
```
事件流格式:
data: {"role": "assistant", "content": "你"}

data: {"role": "assistant", "content": "好"}

data: {"role": "assistant", "content": "！"}

data: [DONE]  // 结束标志

消息结构:
├─ event: 事件类型 (可选)
├─ data: 消息内容
├─ id: 消息ID (可选)
└─ retry: 重试间隔 (可选)
```

**SSE实现示例**:
```python
# 后端实现
from flask import Flask, Response
import json

app = Flask(__name__)

@app.route('/stream')
def stream():
    def generate():
        for i in range(10):
            data = {"token": f"生成内容 {i}"}
            yield f"data: {json.dumps(data)}\n\n"
        yield "data: [DONE]\n\n"
    return Response(generate(), mimetype='text/plain')
```

```javascript
// 前端实现
const eventSource = new EventSource('/stream');

eventSource.onmessage = function(event) {
  if (event.data === '[DONE]') {
    eventSource.close();
    return;
  }
  const data = JSON.parse(event.data);
  displayContent(data.token);
};

eventSource.onerror = function() {
  eventSource.close();
};
```

## 💰 Token计算

### 计算原理

**Token定义**: 模型处理文本的最小单位

```
Token vs 字符对比:
┌─────────────────────────────────────────┐
│ 文本类型        │ Token估算         │
├─────────────────────────────────────────┤
│ 中文文本        │ 1 Token ≈ 2字     │
│ 英文单词        │ 1 Token ≈ 0.75词  │
│ 代码文本        │ 1 Token ≈ 4字符   │
│ 混合文本        │ 1 Token ≈ 3字符   │
└─────────────────────────────────────────┘

影响因素:
├─ 文本语言
├─ 文本类型
├─ 标点符号
└─ 特殊字符
```

#### 1. 在线工具计算

```
OpenAI Tokenizer:
```

#### 3. Python计算
```python
import tiktoken

def count_tokens(text, model="gpt-3.5-turbo"):
    """计算文本的Token数量"""
    encoder = tiktoken.encoding_for_model(model)
    tokens = encoder.encode(text)
    return len(tokens)

def count_messages_tokens(messages, model="gpt-3.5-turbo"):
    """计算对话消息的Token数量"""
    encoder = tiktoken.encoding_for_model(model)

    # 计算每个消息的Token数量
    tokens_per_message = 3  # 消息格式开销
    tokens_per_name = 1     # name字段开销

    total_tokens = 0
    for message in messages:
        total_tokens += tokens_per_message
        for key, value in message.items():
            if isinstance(value, str):
                total_tokens += len(encoder.encode(value))
                if key == "name":
                    total_tokens += tokens_per_name

    return total_tokens
```

```python
def call_api_with_retry(messages, max_retries=3):
```

```python
class RateLimiter:
    def __init__(self, max_requests=10, time_window=60):
        self.max_requests = max_requests
        self.time_window = time_window
        self.requests = []

    async def wait_for_slot(self):
        now = time.time()
        # 清理过期请求
        self.requests = [req for req in self.requests if now - req < self.time_window]
        if len(self.requests) >= self.max_requests:
            sleep_time = self.time_window - (now - self.requests[0])
            await asyncio.sleep(sleep_time)
        self.requests.append(now)
```
