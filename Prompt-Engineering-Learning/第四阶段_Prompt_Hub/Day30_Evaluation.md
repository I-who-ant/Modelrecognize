```
任务: 评估以下{内容类型}

评估维度: {维度名称,如"代码质量"、"文章可读性"等}

评分标准:
- 优秀 (9-10分): {具体标准}
- 良好 (7-8分): {具体标准}
- 中等 (5-6分): {具体标准}
- 较差 (3-4分): {具体标准}
- 很差 (1-2分): {具体标准}

请输出:
- 评分: {分数}/10
- 评分理由: {具体说明}
- 改进建议: {1-3条}
```

**示例 - 代码质量评估**:
```
任务: 评估以下Python代码

评估对象:
def calc(a, b, op):
    if op == '+':
        return a + b
    elif op == '-':
        return a - b
    elif op == '*':
        return a * b
    elif op == '/':
        return a / b

评估维度: 代码质量

评分标准:
- 优秀 (9-10分): 清晰、健壮、有文档、有测试、无明显问题
- 良好 (7-8分): 逻辑清晰、基本错误处理、有注释
- 中等 (5-6分): 功能可用、但缺少错误处理或文档
- 较差 (3-4分): 有明显bug或严重缺陷
- 很差 (1-2分): 无法运行或逻辑错误

→ 输出:

评分: 5/10 (中等)

评分理由:
✅ 优点:
- 逻辑清晰,基本功能可实现
- 使用了elif结构,避免嵌套

❌ 问题:
1. 缺少类型提示和文档字符串
2. 除零错误未处理 (当b=0且op='/'时会崩溃)
3. 无效操作符未处理 (op='%'时返回None)
4. 函数命名不清晰 ('calc'太泛化)
5. 缺少输入验证

改进建议:
1. 添加完整的错误处理和类型提示
2. 使用更清晰的函数名,如'calculate'或'arithmetic_operation'
3. 添加docstring说明用法和参数

改进后代码示例:
```python
def arithmetic_operation(a: float, b: float, operator: str) -> float:
    """
    执行基本算术运算

    Args:
        a: 第一个操作数
        b: 第二个操作数
        operator: 运算符 (+, -, *, /)

    Returns:
        运算结果

    Raises:
        ValueError: 无效的运算符
        ZeroDivisionError: 除数为零
    """
    if operator == '+':
        return a + b
    elif operator == '-':
        return a - b
    elif operator == '*':
        return a * b
    elif operator == '/':
        if b == 0:
            raise ZeroDivisionError("除数不能为零")
        return a / b
    else:
        raise ValueError(f"不支持的运算符: {operator}")
```

改进后评分: 9/10
```

- 案例代码过于简化,生产环境需要更多考虑

维度4: 完整性 = 6/10 (权重20%)

⚠️ 不足:
- 缺少装饰器链的详细讲解

= 2.8 + 2.25 + 1.4 + 1.2
= 7.65/10

总体评价:
这是一篇质量良好的技术文章,技术准确性和可读性都很出色,适合初学者入门。
文章结构清晰,示例丰富,能够帮助读者快速理解装饰器的核心概念。

2. 【实用性】增加框架实战案例和性能优化建议 (+1.0分潜力)

```
任务: 对比评估Python Web框架

- 选项A: Django (全栈框架)
- 选项B: Flask (微框架)

对比维度:

2. 开发效率
3. 性能表现

5. 文档质量

→ 输出:

| 评估维度 | Django | Flask | FastAPI |
|---------|--------|-------|---------|
| **学习曲线** | 6/10<br>内容多,概念复杂(ORM、模板、中间件等),新手需要时间 | 9/10<br>简单直观,核心概念少,快速上手 | 7/10<br>需要理解异步和类型提示,但文档友好 |
| **开发效率** | 9/10<br>Admin、ORM、认证等开箱即用,快速搭建完整应用 | 7/10<br>灵活但需要自己选择插件,中小项目效率高 | 8/10<br>自动生成API文档,类型提示减少bug,异步提升效率 |

| **文档质量** | 9/10<br>官方文档详尽,中文资源丰富,教程多 | 8/10<br>官方文档清晰,社区教程多,但深度内容少 | 9/10<br>自动生成交互式API文档,官方文档优秀 |
| **社区活跃度** | 9/10<br>成熟稳定,大量企业使用,问题容易找到解决方案 | 8/10<br>社区活跃,资源丰富,更新稳定 | 8/10<br>快速增长中,Issue响应快,但历史积累少 |

详细分析:

**Django** (总分7.8):
- 适合场景: 传统Web应用、内容管理系统、企业级应用
- 核心优势: 全栈完整,开发快速,生态成熟
- 主要劣势: 学习成本高,性能一般,过于"重"
- 典型案例: Instagram、Pinterest、NASA官网

**Flask** (总分7.8):
- 适合场景: 中小型API、原型开发、需要高度定制的项目
- 核心优势: 简单灵活,上手快,可控性强
- 主要劣势: 需要自己搭建很多东西,缺少规范

📋 **场景化推荐:**

选择Django,如果:
- ✅ 需要快速搭建完整的Web应用(前后端)
- ✅ 需要Admin后台管理系统
- ✅ 团队对Django熟悉
- ✅ 项目是传统的服务端渲染Web应用

选择Flask,如果:
- ✅ 项目规模中小型,需要灵活性
- ✅ 团队希望完全控制技术栈
- ✅ 需要快速原型验证
- ✅ 不需要太多内置功能

选择FastAPI,如果:
- ✅ 构建RESTful API或微服务
- ✅ 需要高性能和高并发
- ✅ 团队熟悉类型提示和异步编程
- ✅ 希望自动生成API文档
- ✅ 项目是现代化的前后端分离架构

⚠️ 避免选择FastAPI,如果:
- ❌ 需要传统的服务端模板渲染
- ❌ 团队完全不熟悉异步编程
- ❌ 项目需要大量Django-like的内置功能
```

### 模板4: CoT评估 (分步推理)

```
任务: 详细评估{对象}

评估对象:
{内容}

请按以下步骤评估:

步骤1: 理解目标
- 这个{对象}的目的是什么?
- 目标受众是谁?
- 预期达成什么效果?

步骤2: 分析优点
- 做得好的地方有哪些?
- 为什么这些方面做得好?

步骤3: 识别问题
- 存在哪些不足?
- 这些问题的根本原因是什么?

步骤4: 量化评分
- 基于以上分析,各维度评分

步骤5: 改进建议
- 优先级排序的改进措施
- 预期改进效果

最终评分: {总分}/10
```

```

❌ 3. 缺少个性化 (问题严重度: 中)
表现: 所有用户看到的内容完全一样
根本原因: 可能是技术限制或MVP阶段未实现
影响: 老用户体验不够友好,转化率低

❌ 4. 配送信息不够明显 (问题严重度: 低)
表现: 配送时间和配送费字体较小,颜色较浅
根本原因: 设计时优先考虑美观,忽略实用性
影响: 用户可能点进去才发现配送费高或时间长

步骤4: 量化评分

维度评分:
- 视觉设计: 8/10 (美观度好,但信息密度过高)

- 易用性: 6/10 (信息过载影响易用性)
- 创新性: 5/10 (中规中矩,无明显创新)

加权总分: 6.6/10

步骤5: 改进建议

🔴 优先级P0 (必须改):
1. 精简首屏信息
   - 措施: 移除次要模块,保留搜索+分类+推荐商家

   - 预期: 搜索使用率提升20%

3. 突出配送信息
   - 措施: 配送时间用图标+加粗,配送费0元显示"免配送费"
   - 预期: 减少无效点击,提升用户满意度

🟢 优先级P2 (可以改):
4. 实现基础个性化
   - 措施: 根据历史订单推荐常点商家
   - 预期: 复购率提升10%

最终评分: 6.6/10 (良好但有明显改进空间)

改进后预期得分: 8.5/10

关键建议:
首要任务是信息减负,外卖APP的核心是"快",信息过载与"快"相悖。
参考美团/饿了么的信息层级,他们在这方面已经过多轮优化。

## ⚠️ 常见陷阱

### 陷阱1: 标准过于主观

```
❌ 错误:
"这个设计好看吗? 评分1-10"

✅ 正确:
"评估UI设计,维度:
- 色彩搭配: 符合色彩理论,对比度>4.5
- 布局合理性: 符合格式塔原理
- 品牌一致性: 与品牌指南吻合度"
```

### 陷阱2: 缺少改进建议

```
❌ 错误:
"代码质量: 5分,一般"

✅ 正确:
"代码质量: 5分
问题: 函数过长(120行)、缺少异常处理
建议: 拆分为3个函数、添加try-catch"
```
