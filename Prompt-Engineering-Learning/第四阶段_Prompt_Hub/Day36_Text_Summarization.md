### 核心挑战
- 准确抓住核心信息
- 保持原文的关键内容

- 确保流畅可读

- 过滤冗余信息
- 保持逻辑连贯
- 适应不同摘要风格

## 🎯 快速模板库

### 模板1: 基础摘要 (抽取式)

```
任务: 为以下文本生成摘要

原文:
{文本内容}

要求:
- 长度: {字数限制或压缩比例}
- 保留关键信息
- 简洁清晰

请输出摘要。
```


### 模板2: 分层摘要

```
任务: 生成多级摘要

原文: {文本内容}

输出:
1. 一句话摘要 (20字以内)
2. 核心要点 (50-100字)
3. 详细摘要 (200-300字)

每层摘要逐步增加细节。
```

**示例 - 技术文章摘要**:
```
原文: 《深入理解Python装饰器》(约2000字技术文章)

→ 输出:

【一句话摘要】(18字)
Python装饰器是修改函数行为的高阶函数语法糖。

【核心要点】(95字)
装饰器本质是接受函数作为参数并返回新函数的高阶函数。
使用@decorator语法可简化函数包装。常见应用包括日志记录、
性能测试、权限验证、缓存等。实现时需注意保留原函数元数据
(使用functools.wraps)和处理装饰器参数。类也可作为装饰器。

【详细摘要】(285字)
Python装饰器是一种设计模式,允许在不修改原函数代码的情况下
扩展其功能。核心原理是利用Python的闭包和高阶函数特性。

基础用法:
- 简单装饰器: def decorator(func): def wrapper(): ...; return wrapper
- 装饰器语法: @decorator等价于func = decorator(func)
- 保留元数据: 使用@functools.wraps(func)避免丢失函数名和文档

进阶用法:
- 带参数的装饰器: 需要多层嵌套,返回装饰器函数
- 类装饰器: 实现__call__方法,可维护状态
- 装饰器链: 多个装饰器按从下到上的顺序执行

实战应用:
1. 日志记录: 自动记录函数调用和参数
2. 性能分析: 统计函数执行时间
3. 缓存优化: 使用lru_cache缓存结果
4. 权限控制: 在Web框架中验证用户权限

注意事项包括装饰器执行时机、参数传递、性能开销等。
掌握装饰器可以编写更简洁、可维护的Python代码。

分层好处:
- 快速浏览: 看一句话摘要
- 理解要点: 看核心要点
- 深入了解: 看详细摘要
```

### 模板4: 对比式摘要

```
任务: 生成对比摘要

输入:
- 文本A: {内容}
- 文本B: {内容}

输出:
共同点:
- {相同观点}

不同点:
- A的观点: {...}
- B的观点: {...}

总结: {综合对比结论}
```

**示例 - 观点对比**:
```
输入:
文本A: 《为什么远程办公提升效率》
文本B: 《远程办公的陷阱与挑战》

→ 对比摘要:

【共同点】
- ✅ 都认同远程办公是趋势
- ✅ 都提到技术工具的重要性(Zoom、Slack等)
- ✅ 都强调沟通的关键性

【不同点】

关于效率:
- 文本A观点: 远程办公提升效率20-30%
  * 理由: 减少通勤时间,更专注,灵活安排时间
  * 数据支持: Stanford研究显示生产力提升13%

- 文本B观点: 远程办公可能降低效率
  * 理由: 沟通成本增加,协作困难,边界模糊
  * 数据支持: 微软研究显示会议时间增加10%

关于团队协作:
- 文本A: 异步协作更高效,减少打断
- 文本B: 面对面协作更有创造力,远程难以头脑风暴

关于适用场景:
- 文本A: 适合独立性强的工作(编程、写作、设计)
- 文本B: 不适合需要密切协作的项目(创新、紧急项目)

【综合结论】
两篇文章代表了对远程办公的不同视角:
- 文本A更乐观,强调个人效率和灵活性
- 文本B更谨慎,关注团队协作和管理挑战

实际上,远程办公的效果取决于:
1. 工作性质(独立性高 vs 协作性强)
2. 团队文化(是否有远程协作经验)
3. 管理方式(成果导向 vs 过程控制)
4. 个人特质(自律性强 vs 需要监督)

建议: 混合办公模式(部分远程+部分现场)可能是最佳方案,
结合两者优点,避免各自缺点。
```

### 模板5: 问答式摘要

```
任务: 以问答形式总结文本

原文: {文本内容}

输出格式:
Q1: {关键问题1}
A1: {简要回答1}

Q2: {关键问题2}
A2: {简要回答2}

...

适用于: FAQ生成、教学材料、技术文档
```

**示例 - 技术文档Q&A**:
```
原文: 《Kubernetes入门指南》(5000字)

→ 问答式摘要:

Q1: 什么是Kubernetes?
A1: Kubernetes(K8s)是开源的容器编排平台,用于自动化部署、扩展和
    管理容器化应用。由Google开发,2014年开源。

Q2: 为什么需要Kubernetes?
A2: 解决容器化应用的管理问题:
    - 自动部署和回滚
    - 服务发现和负载均衡
    - 自我修复(自动重启失败容器)
    - 自动扩缩容

Q3: Kubernetes的核心概念有哪些?
A3: 主要概念:
    - Pod: 最小部署单元,包含一个或多个容器
    - Service: 定义访问Pod的方式
    - Deployment: 管理Pod的部署和更新
    - Node: 运行Pod的工作机器
    - Cluster: Node的集合

Q4: 如何开始使用Kubernetes?
A4: 学习路径:
    1. 安装Minikube(本地K8s环境)
    2. 学习kubectl命令行工具
    3. 部署第一个应用(Hello World)
    4. 理解YAML配置文件
    5. 实践常用操作(扩展、更新、回滚)

Q5: Kubernetes适合哪些场景?
A5: 适合:
    - 微服务架构
    - 需要高可用的应用
    - 需要自动扩展的应用
    - 多环境部署(开发、测试、生产)

    不适合:
    - 简单的单体应用
    - 团队规模很小(<5人)
    - 学习成本敏感的场景

Q6: Kubernetes有哪些替代方案?
A6: 主要竞品:
    - Docker Swarm: 更简单,但功能较少
    - AWS ECS: AWS原生,与AWS深度集成
    - Nomad: HashiCorp出品,轻量级

    选择建议: K8s是行业标准,生态最完善

Q7: 学习Kubernetes有什么建议?
A7: 学习策略:
    - 从官方文档和教程开始
    - 动手实践(部署真实应用)
    - 理解核心概念后再深入
    - 加入社区(Kubernetes Slack、论坛)
    - 考虑CKA认证(Certified Kubernetes Administrator)
```
