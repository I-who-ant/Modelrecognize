# Day27: Classification - 文本分类提示词模板库

> **应用场景**: 情感分析、主题分类、意图识别、内容审核等

---

## 📝 场景概述

### 核心挑战
- 分类标签定义不清晰
- 边界案例难以判断
- 多标签分类复杂度高
- 需要解释分类理由

### 技术要求
- 准确理解分类标准
- 处理模糊边界情况
- 支持多标签输出
- 提供分类置信度

---

## 🎯 快速模板库

### 模板1: 基础分类 (Zero-Shot)

```
任务: 对以下文本进行分类

分类标签: {标签1, 标签2, 标签3, ...}

文本: {待分类文本}

请直接输出分类结果,格式: 标签名称
```

**示例 - 情感分析**:
```
任务: 对以下文本进行情感分类

分类标签: {正面, 负面, 中性}

文本: "这款产品质量不错,但价格有点贵"

请直接输出分类结果,格式: 标签名称

→ 输出: 中性
```

---

### 模板2: Few-Shot分类 (提升准确率)

```
任务: 对文本进行{分类任务名称}

分类规则:
- {标签1}: {定义和特征}
- {标签2}: {定义和特征}
- {标签3}: {定义和特征}

示例:
1. 文本: "{示例1}"
   分类: {标签A}

2. 文本: "{示例2}"
   分类: {标签B}

3. 文本: "{示例3}"
   分类: {标签C}

现在请对以下文本分类:
文本: "{待分类文本}"
分类:
```

**示例 - 新闻分类**:
```
任务: 对新闻进行主题分类

分类规则:
- 科技: 科技产品、技术创新、互联网相关
- 财经: 经济、金融、股市、公司财报
- 体育: 体育赛事、运动员、比赛结果

示例:
1. 文本: "苹果发布新款iPhone,搭载最新A17芯片"
   分类: 科技

2. 文本: "美联储宣布加息25个基点"
   分类: 财经

3. 文本: "梅西率领阿根廷夺得世界杯冠军"
   分类: 体育

现在请对以下文本分类:
文本: "特斯拉Q4财报超预期,股价大涨10%"
分类:

→ 输出: 财经 (也可能是科技,这是边界案例)
```

### 模板3: CoT分类 (带推理过程)

```
任务: 对文本进行分类,并解释理由

分类标签: {标签列表}

文本: "{待分类文本}"

请按以下格式输出:

步骤1: 识别关键信息
- 关键词:
- 主题:
- 情感倾向:

步骤2: 分析分类依据
- 符合标签特征:
- 不符合标签特征:

步骤3: 最终分类
- 分类结果:
- 置信度: (高/中/低)
- 理由: (一句话说明)
```

**示例 - 客户反馈分类**:
```
任务: 对客户反馈进行分类

分类标签: {产品问题, 服务投诉, 功能建议, 使用咨询}

文本: "你们的APP经常闪退,能不能修复一下啊"

步骤1: 识别关键信息
- 关键词: APP, 闪退, 修复
- 主题: 软件问题
- 情感倾向: 负面,带有不满

步骤2: 分析分类依据
- 符合"产品问题": APP闪退是产品质量问题
- 不符合"服务投诉": 没有提到客服或服务态度
- 不符合"功能建议": 不是新功能请求
- 不符合"使用咨询": 不是询问如何使用

步骤3: 最终分类
- 分类结果: 产品问题
- 置信度: 高
- 理由: 明确描述了APP闪退这一产品质量问题
```

### 模板4: 多标签分类

```
任务: 对文本进行多标签分类 (可选多个标签)

可选标签: {标签1, 标签2, 标签3, ..., 标签N}

文本: "{待分类文本}"

输出格式:
- 主要标签: {最相关的1-2个标签}
- 次要标签: {相关但不主要的标签}
- 不相关标签: {明确不相关的标签}
- 置信度说明: {简要说明为什么选择这些标签}
```

**示例 - 文章标签**:
```
任务: 为文章添加标签

可选标签: {人工智能, 机器学习, 深度学习, Python, 数据科学,
          自然语言处理, 计算机视觉, 应用案例, 技术教程, 行业动态}

文本: "本文介绍如何使用Python和TensorFlow构建一个图像分类模型,
      从数据预处理到模型训练的完整流程"

输出:
- 主要标签: 深度学习, Python, 计算机视觉
- 次要标签: 技术教程, 机器学习
- 不相关标签: 自然语言处理, 行业动态
- 置信度说明:
  * 核心是用Python+TensorFlow做图像分类 → 深度学习+Python+计算机视觉
  * 提供完整流程教程 → 技术教程
  * 也涉及机器学习范畴 → 机器学习(次要)
```

### 模板5: 层级分类

```
任务: 进行两级分类

第一级分类: {大类1, 大类2, 大类3}
第二级分类:
- {大类1}: {子类1-1, 子类1-2, 子类1-3}
- {大类2}: {子类2-1, 子类2-2, 子类2-3}
- {大类3}: {子类3-1, 子类3-2, 子类3-3}

文本: "{待分类文本}"

输出格式:
一级分类:
二级分类:
分类路径: {大类} > {子类}
```

**示例 - 电商商品分类**:
```
任务: 对商品进行分类

第一级: {电子产品, 服装鞋帽, 家居用品}
第二级:
- 电子产品: {手机, 电脑, 数码配件}
- 服装鞋帽: {男装, 女装, 童装}
- 家居用品: {厨具, 家纺, 装饰}

文本: "苹果iPhone 15 Pro Max 256GB 深空黑色"

输出:
一级分类: 电子产品
二级分类: 手机
分类路径: 电子产品 > 手机
```

### 模板6: 置信度分类

```
任务: 对文本分类并给出每个标签的置信度

分类标签: {标签1, 标签2, 标签3, ...}

文本: "{待分类文本}"

输出格式 (按置信度从高到低排序):
1. {标签A}: {置信度百分比}% - {理由}
2. {标签B}: {置信度百分比}% - {理由}
3. {标签C}: {置信度百分比}% - {理由}

推荐分类: {置信度最高的标签}
```

**示例 - 意图识别**:
```
任务: 识别用户意图

分类标签: {查询订单, 退换货, 投诉建议, 咨询产品, 其他}

文本: "我买的东西还没到,能帮我查一下吗"

输出:
1. 查询订单: 85% - 明确提到"查一下"未收到的商品
2. 投诉建议: 10% - 可能隐含对物流速度的不满
3. 咨询产品: 3% - 不太可能,已经购买了
4. 退换货: 2% - 没有明确退换货意图
5. 其他: 0%

推荐分类: 查询订单
```

### 模板7: 边界案例处理

```
任务: 对边界案例进行分类,并标注不确定性

分类标签: {标签列表}

文本: "{待分类文本}"

分析流程:
1. 初步判断: {最可能的1-2个标签}
2. 边界分析: {这个case为什么难以判断}
3. 决策依据: {选择某个标签的关键理由}
4. 不确定性: {高/中/低}
5. 建议: {如果不确定性高,给出人工复核建议}

最终分类: {标签}
```

**示例 - 内容审核**:
```
任务: 对用户评论进行内容审核

分类标签: {正常, 低俗, 辱骂, 广告, 政治敏感}

文本: "这个东西真tm差劲,浪费我的钱"

分析流程:
1. 初步判断: 正常 或 辱骂
2. 边界分析:
   - 有"tm"这样的粗俗用语,但主要是表达不满
   - 没有人身攻击,只是对产品的负面评价
3. 决策依据:
   - 虽然用语粗俗,但属于正常的消费者投诉范畴
   - 没有针对他人的辱骂
4. 不确定性: 中
5. 建议: 可标记为"需人工复核"或"边界案例"

最终分类: 正常 (但需要提醒用户注意用语文明)
```

### 模板8: Self-Consistency分类 (高准确率)

```
任务: 使用多路径验证进行分类

分类标签: {标签列表}

文本: "{待分类文本}"

请用3种不同的角度分析,然后投票决定:

角度1 - 关键词分析:
- 提取关键词:
- 基于关键词的分类:

角度2 - 语义分析:
- 整体语义:
- 基于语义的分类:

角度3 - 上下文分析:
- 隐含信息:
- 基于上下文的分类:

投票结果:
- 角度1: {标签A}
- 角度2: {标签B}
- 角度3: {标签C}

最终分类: {出现次数最多的标签}
一致性: {3/3一致 或 2/3一致 或 1/3不一致}
```

## 💡 最佳实践

### 1. 选择合适的模板

```
简单场景 (2-3个标签,边界清晰):
└─ 使用模板1: 基础Zero-Shot分类

复杂场景 (5+个标签,边界模糊):
└─ 使用模板2: Few-Shot + 模板3: CoT推理

高准确率要求:
└─ 使用模板8: Self-Consistency多路径验证

多标签场景:
└─ 使用模板4: 多标签分类

层级场景:
└─ 使用模板5: 层级分类

边界案例多:
└─ 使用模板7: 边界案例处理
```

### 2. 优化技巧

**提升准确率**:
1. 提供清晰的标签定义和特征
2. 给出3-5个高质量示例 (Few-Shot)
3. 要求模型解释分类理由 (CoT)
4. 使用多路径验证 (Self-Consistency)

**处理边界案例**:
1. 明确标注"不确定"情况
2. 提供人工复核机制
3. 给出置信度评分
4. 记录边界案例用于优化

**多标签场景**:
1. 区分主要标签和次要标签
2. 设置标签选择阈值
3. 允许"无相关标签"选项
4. 解释每个标签的相关性

## 📊 效果评估

### 评估指标

```
准确率 (Accuracy):
- 正确分类数 / 总数
- 目标: > 90%

精确率 (Precision):
- 真阳性 / (真阳性 + 假阳性)
- 目标: > 85%

召回率 (Recall):
- 真阳性 / (真阳性 + 假阴性)
- 目标: > 85%

F1分数:
- 2 * (Precision * Recall) / (Precision + Recall)
- 目标: > 85%
```

### A/B测试

```
对比维度:
1. Zero-Shot vs Few-Shot
2. 有CoT vs 无CoT
3. 单路径 vs Self-Consistency
4. 不同示例数量 (3 vs 5 vs 10)

测试数据集: 100-500个标注样本
统计显著性: p < 0.05
```

## ⚠️ 常见陷阱

### 陷阱1: 标签定义不清

```
❌ 错误:
分类标签: {好, 坏, 一般}

✅ 正确:
分类标签:
- 好: 明确正面评价,没有负面内容
- 坏: 明确负面评价,没有正面内容
- 一般: 既有正面也有负面,或中立态度
```

### 陷阱2: 示例质量差

```
❌ 错误 (示例太相似):
示例1: "这个很好"
示例2: "这个不错"
示例3: "这个挺好"

✅ 正确 (示例多样化):
示例1: "产品质量超出预期,非常满意"
示例2: "价格实惠,性价比高"
示例3: "物流速度快,包装完好"
```

### 陷阱3: 忽略边界案例

```
❌ 错误: 强制每个case都给出明确分类

✅ 正确: 识别并标注不确定的case
- 分类结果: {标签}
- 置信度: 低 (40%)
- 建议: 人工复核
```
