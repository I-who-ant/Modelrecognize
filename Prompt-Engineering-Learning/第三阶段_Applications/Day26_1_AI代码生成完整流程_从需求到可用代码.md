## 📊 应用场景的4个难度等级

### 难度1: 简单脚本 (⭐ 最容易)

```
例子: 数据处理、自动化、测试脚本
成功率: 85%+
审查: 基本代码审查
风险: 低
建议: 可以直接用,最多小改

特征:
  ✓ 逻辑简单
  ✓ 没有复杂依赖
  ✓ 一次生成就能用
```

### 难度2: 标准模块 (⭐⭐)

```
例子: CRUD API, 数据模型, 配置类
成功率: 70%+
审查: 功能+代码审查
风险: 中
建议: 需要2-3轮改进,但最终质量高

特征:
  ✓ 有明确的接口
  ✓ 标准的设计模式
  ✓ 可预测的问题
```

### 难度3: 完整功能 (⭐⭐⭐)

```
例子: 认证系统, 支付集成, 数据分析模块
成功率: 50-70%
审查: 严格功能+安全+代码审查
风险: 高
建议: 需要多轮迭代,必须严格审查

特征:
  ✗ 逻辑复杂
  ✗ 安全性关键
  ✗ 需要多个文件
```

### 难度4: 架构设计 (⭐⭐⭐⭐)

```
例子: 项目骨架, 分层架构, 设计模式
成功率: 30-50%
审查: 架构+代码审查
风险: 中(架构层)
建议: 作为参考和骨架,需要人工完成

特征:
  ✗ 需要全局思考
  ✗ 决策点多
  ✗ 需要经验判断
```

## 🏆 代码质量的5个指标

按重要性排序:

| 优先级 | 指标 | 说明 | 目标 |
|--------|------|------|------|
| 🔴 最高 | **正确性** | 代码实现了需求功能 | 100% |
| 🟠 高 | **可读性** | 易于理解和维护 | 命名清晰、注释完整 |
| 🟡 中 | **可维护性** | 易于修改和扩展 | 圈复杂度<10、函数<50行 |
| 🟢 中 | **安全性** | 没有已知漏洞 | 防SQL注入、XSS、权限检查 |
| 🔵 较低 | **性能** | 运行效率合理 | 算法复杂度可接受 |

## ⚙️ 代码生成的5步工作流

### 第1步: 需求分析 (10%)

```
任务:
  □ 清晰描述需要什么功能
  □ 列出所有边界情况
  □ 确认技术栈
  □ 检查依赖限制

关键问题:
  • 这个功能的输入是什么?
  • 期望的输出格式?
  • 需要处理哪些错误?
  • 有性能要求吗?
```

### 第2步: 设计和规划 (15%)

```
任务:
  □ 确定架构和模块
  □ 设计数据结构
  □ 预见复杂点
  □ 规划测试策略

注意:
  • 复杂功能要拆分成多个模块
  • 先考虑接口设计
  • 想想会遇到的坑
```

### 第3步: 编写生成提示词 (20%)

```
任务:
  □ 遵循5部分结构
  □ 提供清晰示例
  □ 列出所有约束
  □ 明确质量要求

提示:
  • 越详细的需求 = 越好的代码
  • 给例子比描述更清楚
  • 不要遗漏任何约束
```

### 第4步: 生成和迭代 (30%)

```
流程:
  1. 调用AI生成初版代码
  2. 测试和评估
  3. 找出问题(语法/功能/质量)
  4. 基于反馈继续对话改进
  5. 重复2-4直到满意 (通常2-3轮)

评估标准:
  ✓ 语法正确?
  ✓ 逻辑完整?
  ✓ 错误处理?
  ✓ 有文档和注释?
  ✓ 有类型提示?
```

### 第5步: 集成和验证 (25%)

```
任务:
  □ 集成到项目中
  □ 运行完整测试
  □ 性能评估
  □ 编写使用文档

检查清单:
  ✓ 代码符合项目规范?
  ✓ 依赖都安装了?
  ✓ 测试全部通过?
  ✓ 没有性能问题?
```

## 🔄 迭代对话策略(最关键!)

```
初始需求
    ↓
AI生成代码 (第1版)
    ↓
评估代码质量 (打分0-1)
    ↓
质量≥0.85? ──YES→ 完成! ✓
    │
    NO
    ↓
找出问题 (语法/逻辑/质量)
    ↓
写改进建议给AI
    ↓
AI基于反馈改进代码 (第2版)
    ↓
评估新代码
    ↓
质量≥0.85? ──YES→ 完成! ✓
    │
    NO (最多5轮)
    ↓
继续迭代...
```

**关键**: 不要一次要求完美,分阶段迭代效果更好!

## 💻 完整代码示例

### 示例1: 简单函数 (10分钟搞定)

```python
# 生成提示词
你是Python专家。生成一个函数计算BMI。

需求:
1. 参数: weight(公斤), height(米)
2. 返回: BMI值(保留2位小数)
3. 处理异常: 参数无效时抛出ValueError
4. 包含类型提示和docstring
5. 包含单元测试

示例:
>>> calculate_bmi(70, 1.75)
22.86
>>> calculate_bmi(-70, 1.75)
ValueError: Weight must be positive

# 这样的提示词通常一次就能生成完美的代码!
```

### 示例2: API端点 (30分钟,需要2-3轮)

```python
# 第1个提示词
生成一个FastAPI的POST端点/users/login

功能:
  • 接收email和password
  • 验证用户(从数据库)
  • 成功返回JWT token
  • 失败返回401错误

框架: FastAPI
认证: JWT token
    ↓
[AI生成第1版代码]
    ↓
[你测试发现缺少密码加密]
    ↓
# 第2个提示词 (改进)
上面的代码缺少密码加密。请改进:
  • 使用bcrypt加密密码
  • 验证密码时用bcrypt对比
  • 添加密码有效性检查
    ↓
[AI改进第2版代码]
    ↓
[你测试发现缺少CORS和日志]
    ↓
# 第3个提示词
添加CORS支持和日志记录
    ↓
[最终版本完成]
```

## 🔒 安全审查清单 (必做!)

```
代码安全检查:
═════════════════════════════════════

□ 数据安全
  ├─ 敏感数据(密钥、密码)硬编码了吗?
  ├─ 用户输入是否验证和过滤?
  └─ 敏感数据是否加密存储?

□ 认证授权
  ├─ 验证用户身份了吗?
  ├─ 检查用户权限了吗?
  └─ Token生成和验证正确吗?

□ SQL注入防护
  ├─ 使用参数化查询了吗?
  ├─ 还是字符串拼接?
  └─ 用ORM了吗?

□ 其他风险
  ├─ 有明显的逻辑漏洞吗?
  ├─ 错误处理完整吗?
  └─ 可能的无限循环或内存泄漏?
```

**重要**: 任何涉及安全的代码(认证、支付、数据)都必须人工审查!

## 📈 难度 vs 时间成本矩阵

```
难度        │ 一次成功率  │ 需要轮数  │ 总耗时
─────────────┼────────────┼──────────┼────────
简单脚本    │ 85%        │ 1-2轮    │ 10分钟
标准模块    │ 70%        │ 2-3轮    │ 30分钟
完整功能    │ 50-70%     │ 3-5轮    │ 1-2小时
架构设计    │ 30-50%     │ 5+轮     │ 参考用,需人工
```

**结论**: 有把握的事情(脚本/模块)可以快速生成,复杂功能需要耐心迭代

## 💪 老王的快速建议

```
代码生成的黄金法则:

1. 不要贪心!
   不要一次生成1000行代码
   分模块生成,每个100-200行

2. 多轮迭代!
   第1版一定不完美
   期待需要2-3轮改进

3. 必须测试!
   AI生成的代码不能盲目信任
   必须跑单元测试

4. 安全第一!
   涉及安全的代码必须人工审查
   不要盲目相信AI的安全意识

5. 留下代码历史!
   记录每次迭代的改进
   为将来的维护留下痕迹
```
