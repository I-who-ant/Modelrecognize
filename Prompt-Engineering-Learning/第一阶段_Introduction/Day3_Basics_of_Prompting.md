## 📖 理论学习

### 1. 什么是 Prompting？

**定义**:
Prompting 是与大型语言模型交互的方式，通过设计特定的输入文本（prompt）来引导模型产生期望的输出

**核心概念**:
```
Prompt = 指令 + 上下文 + 示例 + 期望输出格式
```

**与传统编程的区别**:
```
传统编程:
- 精确的算法逻辑
- 确定的执行路径
- 明确的数据类型
- 错误处理机制

Prompting:
- 自然语言描述
- 灵活的理解过程
- 隐含的意图传递
- 概率性的输出
```

### 2. Basic Prompts (基础提示)

#### 2.1 简单示例

**示例 1: 文本补全**
```
Prompt: "The capital of France is"

Output: "the capital of France is Paris."

The capital of France is a city located in the north-central part of the country.
```

**示例 2: 添加指令**
```
Prompt: "Complete the sentence:\nThe capital of France is"

Output: "Paris. The city is known for its art, fashion, and culture."

Complete the sentence:
The capital of France is Paris.
```

#### 2.2 改进方向

```
从简单到优化的转变:

❌ 基础版本:
输入: "The sky is"
问题: 输出不可预测，可能偏离目标

✅ 优化版本:
输入: "Complete the sentence:\nThe sky is"
改进: 明确任务，输出更可控

✅ 高级版本:
输入: "Complete this sentence in a scientific way: The sky is"
改进: 指定语气和风格
```

### 3. Standard Prompts (标准提示格式)

#### 3.1 QA 格式

**标准结构**:
```
格式:
Q: <Question>?
A:

示例:
Q: What is the capital of France?
A:

Q: How does photosynthesis work?
A:
```

**优势**:
```
✅ 结构清晰: 问题与答案分离
✅ 易于理解: 符合人类问答习惯
✅ 模型友好: 训练数据中的常见格式
✅ 可扩展: 可以添加上下文信息
```

#### 3.2 变体格式

**格式 1: 直接问答**
```
问题: <Question>
答案:

示例:
问题: 什么是机器学习？
答案:
```

**格式 2: 任务导向**
```
任务: <Task Description>
输入: <Input>
输出:

示例:
任务: 翻译以下英文句子
输入: "Hello, how are you?"
输出:
```

**格式 3: 角色设定**
```
角色: <Role Description>
任务: <Task>
要求: <Requirements>
输入: <Input>
输出格式: <Format>

示例:
角色: 专业翻译师
任务: 将英文翻译成中文
要求: 保持语言自然流畅
输入: "The future of AI is promising."
输出格式: [原文] -> [译文]
```

### 4. Few-Shot Prompting (小样本提示)

#### 4.1 核心思想

**定义**:
Few-shot prompting 是一种提示技术，通过在提示中提供少量示例来帮助模型理解任务和期望的输出格式。

**数学原理**:
```
P(output|input, examples) ≈ P(output|input, context)

通过示例提供:
- 任务理解
- 模式识别
- 输出格式参考
- 质量标准
```

#### 4.2 基本结构

```
结构格式:
<Example 1 Input>
<Example 1 Output>

<Example 2 Input>
<Example 2 Output>

<Example 3 Input>
<Example 3 Output>

<New Input>
<Expected Output (blank)>
```

#### 4.3 实际示例

**示例 1: 情感分析**
```
例子 1:
文本: "I love this product!"
标签: 积极

例子 2:
文本: "This is terrible."
标签: 消极

例子 3:
文本: "It's okay, nothing special."
标签: 中性

现在，请分析以下文本的情感倾向:
文本: "The service was excellent!"

标签:
```

**示例 2: 文本摘要**
```
例子 1:
原文: "今天天气很好，阳光明媚，温度适宜。是一个适合外出游玩的好日子。"
摘要: "天气晴好，适合出游。"

例子 2:
原文: "人工智能技术在近年来取得了显著进展，机器学习、深度学习等技术快速发展。"
摘要: "AI技术快速发展。"

现在，请为以下文本生成摘要:
原文: "这本书详细介绍了Python编程语言的基础知识和高级特性。"

摘要:
```

#### 4.4 最佳实践

```
Few-shot 设计原则:
✅ 示例数量: 2-5 个最佳
✅ 示例质量: 高质量、准确的示例
✅ 格式一致: 所有示例保持相同格式
✅ 多样性: 涵盖不同的输入类型
✅ 清晰性: 示例应该易于理解

常见错误:
❌ 示例格式不一致
❌ 示例质量过低
❌ 示例数量过多 (超过 5 个)
❌ 示例与任务不相关
❌ 缺少明确的输入输出边界
```

### 5. Zero-shot vs Few-shot 对比

#### 5.1 性能对比

| 对比维度 | Zero-shot | Few-shot | 最佳选择 |
|----------|-----------|----------|----------|
| **准确性** | 中等 | 高 | 任务复杂时用 Few-shot |
| **速度** | 快 | 中等 | 快速响应时用 Zero-shot |
| **成本** | 低 | 中等 | 成本敏感时用 Zero-shot |
| **灵活性** | 高 | 中等 | 需要灵活性时用 Zero-shot |
| **学习能力** | 无 | 有 | 复杂模式时用 Few-shot |

#### 5.2 适用场景

**Zero-shot 适用场景**:
```
✅ 简单直接的任务
✅ 常见知识问答
✅ 创意写作
✅ 快速原型开发
✅ 成本敏感应用
```

**Few-shot 适用场景**:
```
✅ 复杂模式识别
✅ 特定领域任务
✅ 格式要求严格
✅ 需要示例引导
✅ 质量要求较高
```

### 6. Prompt 的层次结构

#### 6.1 四个层次

```
层次 1: 任务描述层
- 明确说明要做什么
- 定义成功标准
- 设定约束条件

层次 2: 上下文信息层
- 提供必要的背景
- 包含相关信息
- 说明使用场景

层次 3: 示例引导层
- 提供参考示例
- 展示期望输出
- 传递模式信息

层次 4: 输出格式层
- 指定输出结构
- 定义格式要求
- 控制输出长度
```

#### 6.2 实际应用

**简单任务 (层次 1)**:
```
提示: "将以下文本翻译成英文: 今天天气很好。"
(只包含任务描述)
```

**中等任务 (层次 1+4)**:
```
提示: "翻译以下中文句子为英文，要求保持原意，语言自然流畅。
输出格式: [中文] -> [英文]

今天天气很好。"
(任务描述 + 输出格式)
```

**复杂任务 (层次 1+2+3+4)**:
```
角色: 专业翻译师
任务: 将中文技术文档翻译成英文
要求: 保持专业术语准确性，语言自然流畅
上下文: 这是AI技术文档的目标读者是外国开发者

示例:
中文: "深度学习是一种机器学习方法。"
英文: "Deep learning is a machine learning method."

现在，请翻译:
中文: "神经网络通过多层非线性变换来学习数据的复杂模式。"

输出格式: [中文原文] -> [英文译文]
(角色 + 任务 + 要求 + 上下文 + 示例 + 格式)
```

### 7. 提示工程的基本原则

#### 7.1 CLEAR 原则

```
C - Clear (清晰)
- 使用明确的语言
- 避免歧义表达
- 具体描述需求

L - Logical (逻辑)
- 结构清晰合理
- 步骤明确有序
- 因果关系清晰

E - Explicit (明确)
- 直接说明期望
- 具体规定格式
- 明确成功标准

A - Appropriate (适当)
- 长度适中
- 复杂度匹配
- 格式规范

R - Reusable (可重用)
- 模块化设计
- 模板化结构
- 参数化内容
```

#### 7.2 迭代优化原则

```
优化流程:
1. 初始设计
   - 基础需求分析
   - 初步提示设计
   - 基本功能测试

2. 问题识别
   - 输出质量评估
   - 失败案例分析
   - 问题根因定位

3. 提示改进
   - 添加必要信息
   - 优化表达方式
   - 调整结构布局

4. 验证测试
   - 多场景测试
   - 性能对比评估
   - 稳定性验证

5. 持续优化
   - 收集反馈
   - 分析数据
   - 迭代改进
```
