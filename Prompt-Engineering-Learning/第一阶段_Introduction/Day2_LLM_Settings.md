## 📖 理论学习

### 1. 什么是 LLM Settings？

**定义**:
LLM Settings 是影响语言模型输出行为的可配置参数，通过调整这些参数可以控制生成文本的确定性、创造性、长度等特性。

**核心作用**:
```
参数调整 → 输出控制 → 任务适配 → 性能优化
```

### 2. Temperature (温度) - 最重要参数

#### 2.1 原理机制

**数学原理**:
```
p(token_i) = softmax(scores_i / temperature)

当 temperature = 0:
- 只选择最高概率的 token
- 输出完全确定性

当 temperature = 1:
- 保持原始概率分布
- 输出自然的随机性

当 temperature > 1:
- 降低高概率 token 的权重
- 增加低概率 token 的可能性
- 输出更加随机
```

#### 2.2 实际应用值域

| Temperature | 特性 | 适用场景 |
|-------------|------|----------|
| **0.0-0.2** | 高度确定性 | 事实问答、数学计算、代码生成 |
| **0.3-0.5** | 较确定性 | 摘要生成、数据提取、分类 |
| **0.6-0.8** | 平衡创造性和一致性 | 通用对话、写作助手 |
| **0.9-1.0** | 高度创造性 | 创意写作、头脑风暴、诗歌 |
| **>1.0** | 极度随机 | 实验性任务、探索性生成 |

#### 2.3 最佳实践

```
实践经验:
✅ 0.2 以下: 代码生成、数学推理
✅ 0.3-0.7: 日常对话和写作
✅ 0.8 以上: 创意性任务

❌ 避免:
- 单一任务使用极端值 (0 或 2.0)
- 不考虑任务特点盲目设置
- 同时调整多个参数而不测试
```

### 3. Top-p (核采样)

#### 3.1 原理机制

**概念**:
Top-p 是一种基于累积概率的采样方法，选择概率质量总和达到 p 的最小 token 集合作为候选。

**计算过程**:
```
1. 计算所有 token 的概率: p₁, p₂, ..., pₙ
2. 按概率降序排列
3. 选择前 k 个 token，使得 Σᵢ₌₁ᵏ pᵢ ≥ p
4. 在选中的 token 中随机采样
```

**示例**:
```
原始概率分布:
token:  [the, to, a, and, is, of, in, that, ...]
prob:   [0.12, 0.08, 0.06, 0.05, 0.04, 0.03, 0.02, 0.02, ...]

Top-p = 0.8 时:
累积: [0.12, 0.20, 0.26, 0.31, 0.35, 0.38, 0.40, 0.42, ...]
选择: [the, to, a, and, is, of, in, that]
(前 8 个 token 的累积概率 ≥ 0.8)
```

#### 3.2 与 Temperature 的关系

| Top-p | 特性 | 推荐 Temperature |
|-------|------|-----------------|
| **0.1-0.3** | 高确定性 | 0.2-0.5 |
| **0.4-0.6** | 中等确定性 | 0.5-0.8 |
| **0.7-0.9** | 低确定性 | 0.8-1.0 |
| **0.95-1.0** | 高创造性 | 0.9-1.2 |

#### 3.3 使用建议

```
核心原则:
✅ 避免 Top-p 和 Temperature 同时设置为高值
✅ 优先调整 Temperature，其次调整 Top-p
✅ 创造性任务: Top-p=0.9, Temperature=0.9
✅ 事实性任务: Top-p=0.3, Temperature=0.2

最佳组合:
🎯 事实问答: Temperature=0.2, Top-p=0.5
🎯 创意写作: Temperature=0.8, Top-p=0.9
🎯 代码生成: Temperature=0.1, Top-p=0.3
🎯 对话助手: Temperature=0.7, Top-p=0.8
```

### 4. Max Tokens (最大长度)

#### 4.1 作用机制

**定义**:
控制模型生成的最大 token 数量，限制输出长度，防止过度生成。

**重要性**:
```
成本控制: token 数量直接影响费用
质量控制: 防止输出冗余或偏离主题
性能优化: 减少计算时间
任务适配: 确保输出符合需求
```

#### 4.2 设置策略

| 任务类型 | 推荐 Max Tokens | 原因 |
|----------|-----------------|------|
| **简短回答** | 50-150 | 直接回答，无需冗余 |
| **中等说明** | 200-500 | 详细解释，保持简洁 |
| **长文生成** | 800-1500 | 完整文章，控制质量 |
| **代码生成** | 300-800 | 完整函数，避免截断 |
| **创意写作** | 1000-2000 | 充分展开，保持连贯 |

#### 4.3 优化技巧

```
优化策略:
✅ 估算需求: 根据任务复杂度估算
✅ 分段生成: 长任务分成多个请求
✅ 动态调整: 根据前文内容调整
✅ 成本计算: 监控 token 使用量

计算方法:
1 token ≈ 0.75 个英文单词
1 token ≈ 1 个中文汉字
- 100 字文章 ≈ 133 tokens
- 200 字说明 ≈ 267 tokens
```

### 5. Frequency Penalty (频率惩罚)

#### 5.1 原理机制

**作用**:
降低已出现 token 的出现频率，鼓励模型使用多样化的表达方式。

**数学表示**:
```
调整后概率 = 原始概率 × (1 - frequency_penalty)^frequency

当 frequency_penalty = 0:
- 不做任何调整

当 frequency_penalty = 0.5:
- 已出现 2 次的 token 概率降低 25%
- 已出现 5 次的 token 概率降低 76%

当 frequency_penalty = 1.0:
- 避免重复，鼓励多样性
```

#### 5.2 应用场景

```
适用场景:
✅ 长文本生成: 避免词汇重复
✅ 创意写作: 增加表达多样性
✅ 产品描述: 丰富语言表达
✅ 技术文档: 避免术语堆砌

不适用场景:
❌ 关键词重复强调时
❌ 专业术语固定表达
❌ 法律/技术文档的规范性要求
❌ 诗歌中的重复修辞
```

#### 5.3 最佳实践

```
推荐设置:
- 轻度惩罚 (0.1-0.3): 日常对话，保持自然
- 中度惩罚 (0.4-0.6): 文章写作，增加多样性
- 重度惩罚 (0.7-1.0): 创意生成，极力避免重复

使用建议:
✅ 与 Temperature 配合使用
✅ 针对不同任务调整强度
✅ 测试不同设置的效果
❌ 不要过度使用 (避免影响连贯性)
```

### 6. Presence Penalty (存在惩罚)

#### 6.1 原理机制

**作用**:
无论 token 出现过多少次，都给予相同的惩罚力度，鼓励模型引入新概念。

**与 Frequency Penalty 的区别**:
```
Frequency Penalty:
- 基于出现次数动态调整
- 次数越多，惩罚越重
- 适合控制重复频率

Presence Penalty:
- 基于是否出现过二值化
- 出现过就惩罚，不考虑次数
- 鼓励引入新内容
```

#### 6.2 应用场景

```
适用场景:
✅ 头脑风暴: 鼓励新想法
✅ 产品创意: 激发创新
✅ 研究探索: 避免固定思维
✅ 自由写作: 突破常规表达

不适用场景:
❌ 技术文档: 需要准确术语
❌ 事实陈述: 需要准确信息
❌ 重复强调: 有意强调重点
```

### 7. Stop Sequences (停止序列)

#### 7.1 定义和使用

**定义**:
设置特定的字符串作为停止信号，模型遇到这些序列时停止生成。

**应用场景**:
```
实用例子:
✅ 代码生成: stop = ["\n\n\n", "```"]
✅ 列表生成: stop = ["\n", "\n\n"]
✅ 问答系统: stop = ["\n\n", "Q:"]
✅ 多轮对话: stop = ["Human:", "Assistant:"]
```
