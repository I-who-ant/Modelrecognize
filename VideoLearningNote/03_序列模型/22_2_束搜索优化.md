## 🎯 优化 1: 长度归一化 (Length Normalization)

### 核心思想

```
长度归一化:
  score_normalized = score / length^α

其中:
  α ∈ [0, 1] 是超参数
  α = 0: 不归一化 (原始束搜索)
  α = 1: 完全归一化 (平均对数概率)
  α = 0.6-0.7: 实践中常用
```

### 可视化示例

```
任务: "I love you" → 中文翻译
beam_size = 2

无长度归一化 (α=0):
═══════════════════

候选1: "我爱你"
  原始分数 = -0.8
  归一化分数 = -0.8 / 3^0 = -0.8
  → 选择 ✓

候选2: "我非常爱你"
  原始分数 = -1.15
  归一化分数 = -1.15 / 4^0 = -1.15
  → 拒绝 ✗

原因: 系统偏好短序列


有长度归一化 (α=0.7):
═══════════════════

候选1: "我爱你"
  原始分数 = -0.8
  归一化分数 = -0.8 / 3^0.7 = -0.8 / 2.41 = -0.33

候选2: "我非常爱你"
  原始分数 = -1.15
  归一化分数 = -1.15 / 4^0.7 = -1.15 / 2.91 = -0.40

候选3: "我非常非常爱你"
  原始分数 = -1.45
  归一化分数 = -1.45 / 5^0.7 = -1.45 / 3.35 = -0.43

结果: 选择 "我爱你" (分数-0.33)
但: "我非常爱你" (分数-0.40) 与最优差距缩小!

如果 "我非常非常爱你" 真的是更好翻译:
  原始分数 = -1.2 (更高质量)
  归一化分数 = -1.2 / 5^0.7 = -0.36
  → 可能被选中! ✅
```

### Google 公式 (更稳健)

```
Google's NMT (Wu et al., 2016) 使用:
  score_normalized = score / ((5 + length) / 6)^α

优势:
  - 避免除以太小的数
  - 更平滑的归一化曲线
  - 实践中表现更好

示例:
  length = 3: (5+3)/6 = 1.33
  length = 5: (5+5)/6 = 1.67
  length = 10: (5+10)/6 = 2.5
```

### 代码实现

```python
import math
import torch
import torch.nn.functional as F

def length_penalty(length, alpha=0.6):
    """
    长度惩罚函数

    参数:
        length: 序列长度
        alpha: 归一化系数

    返回:
        penalty: 惩罚因子
    """
    # Google NMT 公式
    return ((5 + length) / 6) ** alpha

def beam_search_with_length_norm(model, encoder_output,
                                 beam_size=5, max_len=50,
                                 alpha=0.6, sos_id=1, eos_id=2):
    """
    带长度归一化的束搜索

    参数:
        model: 序列到序列模型
        encoder_output: 编码器输出
        beam_size: 束宽
        max_len: 最大生成长度
        alpha: 长度归一化系数
        sos_id: 开始符号 ID
        eos_id: 结束符号 ID

    返回:
        best_sequence: 最佳序列
        best_score: 最佳分数 (归一化后)
    """
    # 初始化候选
    init_hidden = model.decoder.init_hidden(encoder_output)
    candidates = [
        ([sos_id], 0.0, 1, init_hidden)  # (seq, raw_score, length, hidden)
    ]

    finished = []

    for t in range(max_len):
        all_candidates = []

        for seq, score, length, hidden in candidates:
            # 如果已完成，添加到 finished
            if seq[-1] == eos_id:
                finished.append((seq, score, length))
                continue

            # 解码一步
            last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
            output, new_hidden = model.decoder(
                last_word, hidden, encoder_output
            )

            # 计算对数概率
            log_probs = F.log_softmax(output.squeeze(0).squeeze(0), dim=0)

            # 获取前 beam_size 个词
            top_log_probs, top_indices = torch.topk(
                log_probs, beam_size
            )

            # 创建新候选
            for log_prob, word_id in zip(top_log_probs, top_indices):
                new_seq = seq + [word_id.item()]
                new_raw_score = score + log_prob.item()
                new_length = length + 1

                # 计算归一化分数
                penalty = length_penalty(new_length, alpha)
                normalized_score = new_raw_score / penalty

                all_candidates.append(
                    (new_seq, new_raw_score, new_length, new_hidden, normalized_score)
                )

        # 如果没有新候选，停止
        if not all_candidates:
            break

        # 按归一化分数排序
        all_candidates.sort(key=lambda x: x[4], reverse=True)
        candidates = all_candidates[:beam_size]

        # 早停: 如果有足够多完成序列
        if len(finished) >= beam_size:
            break

    # 添加未完成的候选到 finished
    for seq, score, length in candidates:
        if seq[-1] != eos_id:
            finished.append((seq, score, length))

    # 按归一化分数选择最佳
    finished.sort(key=lambda x: x[1] / length_penalty(x[2], alpha), reverse=True)
    best_seq, best_raw_score, best_length = finished[0]

    return best_seq
```

### 实践建议

```
超参数选择:
═══════════

α = 0.0:
  - 完全不归一化
  - 偏向短序列
  - 适合: 诗歌生成 (追求简洁)

α = 0.6-0.7:
  - 平衡短长序列
  - 适合大多数任务
  - 推荐: 机器翻译、摘要

α = 1.0:
  - 完全基于平均概率
  - 可能偏向长序列
  - 适合: 对话系统 (追求自然)
```

## 🎯 优化 2: 覆盖惩罚 (Coverage Penalty)

### 核心思想

```
覆盖惩罚 (Coverage Penalty):
  惩罚重复关注源序列的同一部分

数学表达:
  coverage[s] = Σₜ attention[t, s]

  penalty = λ · Σₛ min(coverage[s], 1)

  final_score = raw_score - penalty

其中:
  - coverage[s]: 源序列第 s 个位置的总关注度
  - λ ∈ [0, 1]: 惩罚系数 (通常 0.1-0.5)
  - 如果 coverage[s] > 1，说明过度关注该位置
```

### 可视化示例

```
场景: 英译中 "I love love love you"
来源: "I [0] love [1] love [2] love [3] you [4]"

理想注意力分布:
═══════════════
目标词:   I  非常  爱  爱  爱  你 们
来源词:  ↓  ↓   ↓   ↓   ↓   ↓   ↓
        [0][1] [2] [3] [4]
        1.0 0.1 0.3 0.2 0.1  (合理分布)

问题注意力分布:
══════════════
目标词:   I  非常  爱  爱  爱  你 们
来源词:  ↓  ↓   ↓   ↓   ↓   ↓   ↓
        [0][1] [2] [3] [4]
        1.0 0.0 1.0 1.0 1.0  (过度关注 love!)

覆盖向量计算:
════════════
coverage = [1.0, 0.0, 1.0, 1.0, 1.0]

覆盖惩罚:
  penalty = 0.5 × [min(1.0,1) + min(0.0,1) + min(1.0,1) + min(1.0,1) + min(1.0,1)]
          = 0.5 × (1 + 0 + 1 + 1 + 1)
          = 0.5 × 4 = 2.0

最终分数调整:
  原始分数: -2.5
  最终分数: -2.5 - 2.0 = -4.5 (大幅降低!)
```

### 代码实现

```python
def coverage_penalty(attention_weights, beta=0.5):
    """
    计算覆盖惩罚

    参数:
        attention_weights: [target_len, source_len]
                          每个目标词对每个源词的注意力
        beta: 惩罚系数 (通常 0.1-0.5)

    返回:
        penalty: 标量惩罚值
    """
    # 计算覆盖向量
    # coverage[s] = sum_t attention[t, s]
    coverage = attention_weights.sum(dim=0)  # [source_len]

    # 惩罚过度覆盖的位置
    # 对每个源位置，如果 coverage > 1，则给予惩罚
    penalty = beta * torch.sum(torch.log(coverage + 1e-10))

    return penalty.item()


def beam_search_with_coverage(model, encoder_output,
                              beam_size=5, beta=0.5):
    """
    带覆盖惩罚的束搜索
    """
    init_hidden = model.decoder.init_hidden(encoder_output)
    candidates = [
        ([sos_id], 0.0, init_hidden, torch.zeros(1, encoder_output.size(1)))
    ]
    # 最后一项: 当前覆盖向量 [1, source_len]

    finished = []

    for t in range(max_len):
        all_candidates = []

        for seq, score, hidden, coverage in candidates:
            if seq[-1] == eos_id:
                finished.append((seq, score))
                continue

            last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
            output, new_hidden, attention = model.decoder(
                last_word, hidden, encoder_output
            )
            # attention: [1, 1, source_len]

            log_probs = F.log_softmax(output.squeeze(0).squeeze(0), dim=0)
            top_log_probs, top_indices = torch.topk(log_probs, beam_size)

            for log_prob, word_id in zip(top_log_probs, top_indices):
                new_seq = seq + [word_id.item()]
                new_score = score + log_prob.item()

                # 更新覆盖向量
                new_coverage = coverage + attention.squeeze(0).squeeze(0)

                # 计算覆盖惩罚
                cp = coverage_penalty(new_coverage, beta)
                final_score = new_score - cp

                all_candidates.append(
                    (new_seq, new_score, new_hidden, new_coverage, final_score)
                )

        if not all_candidates:
            break

        # 按最终分数 (包含惩罚) 排序
        all_candidates.sort(key=lambda x: x[4], reverse=True)
        candidates = all_candidates[:beam_size]

        if len(finished) >= beam_size:
            break

    finished.extend(candidates)
    finished.sort(key=lambda x: x[1], reverse=True)

    return finished[0][0], finished[0][1]
```

```
效果对比:
═══════

无覆盖惩罚:
  生成: "我 爱 爱 爱 你"
  覆盖惩罚: 0.0
  最终分数: -2.5

有覆盖惩罚 (β=0.5):

  覆盖惩罚: 0.3
  最终分数: -1.6

结果: 系统选择覆盖更均匀的序列!
```

## 🎯 优化 3: 多样性促进 (Diversity Promotion)

### 问题分析

```
为什么需要多样性?
═════════════════

传统束搜索的问题:
  所有 k 个候选来自同一个搜索路径
  只在后期开始分化
  → 候选高度相似

示例 (beam_size=3):
  候选1: "我 爱 你"
  候选2: "我 非常 爱 你"
  候选3: "我 真的 爱 你"

问题: 都是 "我...爱你" 的变体
     缺乏真正不同的表达方式
```

### 方法 1: 温度采样 (Temperature Sampling)

```
核心思想:
════════

不总是选择概率最高的词
而是从概率分布中采样
  P'(w) = P(w)^(1/T) / Σ P(w)^(1/T)

参数 T (温度):
  T > 1: 更平滑 (更多样)
  T = 1: 原始分布
  T < 1: 更锐利 (更确定)
```

#### 可视化对比

```
原始概率分布 (T=1):
═══════════════════

词:    我    爱    你    很    非
概率:  0.6   0.8   0.7   0.2   0.1
log:  -0.51 -0.22 -0.36 -1.61 -2.30

总是选择 "爱" (argmax)


温度采样 (T=2.0):
═════════════════

词:    我      爱      你      很      非
概率:  0.6     0.8     0.7     0.2     0.1
应用T: 0.6^0.5 0.8^0.5 0.7^0.5 0.2^0.5 0.1^0.5
     = 0.77   0.89   0.84   0.45   0.32
归一化: 0.27   0.31   0.29   0.16   0.11

可能选择 "你" (0.29) 或 "我" (0.27)!
```

#### 代码实现

```python
def temperature_sampling(logits, temperature=1.0, top_k=50):
    """
    温度采样

    参数:
        logits: [vocab_size] 原始未归一化的对数概率
        temperature: 温度系数 T
        top_k: 只考虑前 k 个最可能的词 (加速)

    返回:
        sampled_id: 采样的词 ID
    """
    # 只保留前 top_k 个词 (加速)
    top_logits, top_indices = torch.topk(logits, top_k)

    # 应用温度
    logits = top_logits / temperature

    # Softmax
    probs = F.softmax(logits, dim=0)

    # 从分布中采样
    sampled_idx = torch.multinomial(probs, 1)

    return top_indices[sampled_idx].item()


def beam_search_with_temperature(model, encoder_output,
                                 beam_size=5, temperature=1.0):
    """
    带温度采样的束搜索
    """
    init_hidden = model.decoder.init_hidden(encoder_output)
    candidates = [([sos_id], 0.0, init_hidden)]

    finished = []

    for t in range(max_len):
        all_candidates = []

        for seq, score, hidden in candidates:
            if seq[-1] == eos_id:
                finished.append((seq, score))
                continue

            last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
            output, new_hidden = model.decoder(
                last_word, hidden, encoder_output
            )

            logits = output.squeeze(0).squeeze(0)

            # 温度采样获取多个候选
            for _ in range(beam_size):
                word_id = temperature_sampling(logits, temperature)
                log_prob = F.log_softmax(logits, dim=0)[word_id]

                new_seq = seq + [word_id]
                new_score = score + log_prob.item()

                all_candidates.append(
                    (new_seq, new_score, new_hidden)
                )

        if not all_candidates:
            break

        all_candidates.sort(key=lambda x: x[1], reverse=True)
        candidates = all_candidates[:beam_size]

        if len(finished) >= beam_size:
            break

    finished.extend(candidates)
    finished.sort(key=lambda x: x[1], reverse=True)

    return finished[0][0], finished[0][1]
```

### 方法 2: 多样性束搜索 (Diverse Beam Search)

```
核心思想:
════════

将束分成 G 个组 (通常 G = beam_size)
每组独立搜索一个候选
组间施加多样性惩罚

公式:
  score_g = raw_score_g - λ × Σ_{g'≠g} similarity(seq_g, seq_{g'})

其中:
  - seq_g: 第 g 组的序列
  - similarity: 序列相似度 (基于 n-gram)
  - λ: 多样性系数
```

#### 代码框架

```python
def diverse_beam_search(model, encoder_output,
                        beam_size=10, num_groups=2, diversity_lambda=0.5):
    """
    多样性束搜索

    参数:
        beam_size: 总束宽
        num_groups: 分组数量
        diversity_lambda: 多样性系数
    """
    group_size = beam_size // num_groups
    groups = [[] for _ in range(num_groups)]

    # 每个组独立初始化
    for g in range(num_groups):
        init_hidden = model.decoder.init_hidden(encoder_output)
        groups[g] = [([sos_id], 0.0, init_hidden)]

    for t in range(max_len):
        all_candidates = []

        for g in range(num_groups):
            for seq, score, hidden in groups[g]:
                if seq[-1] == eos_id:
                    continue

                last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
                output, new_hidden = model.decoder(
                    last_word, hidden, encoder_output
                )

                log_probs = F.log_softmax(output.squeeze(0), dim=-1)
                top_log_probs, top_indices = torch.topk(
                    log_probs, group_size * 2
                )

                # 为每个候选添加多样性惩罚
                for log_prob, word_id in zip(top_log_probs, top_indices):
                    new_seq = seq + [word_id.item()]
                    new_score = score + log_prob.item()

                    # 计算与其他组的多样性惩罚
                    diversity_penalty = 0.0
                    for g2 in range(num_groups):
                        if g2 != g:
                            for other_seq, _, _ in groups[g2]:
                                similarity = ngram_overlap(new_seq, other_seq)
                                diversity_penalty += similarity

                    final_score = new_score - diversity_lambda * diversity_penalty

                    all_candidates.append(
                        (new_seq, final_score, new_hidden, g)
                    )

        # 按组选择
        all_candidates.sort(key=lambda x: x[1], reverse=True)
        for g in range(num_groups):
            group_candidates = [c for c in all_candidates if c[3] == g]
            groups[g] = group_candidates[:group_size]

    # 合并所有组的结果
    all_finished = []
    for g in range(num_groups):
        all_finished.extend(groups[g])

    all_finished.sort(key=lambda x: x[1], reverse=True)
    return all_finished[0][0], all_finished[0][1]
```

## 🎯 优化 4: 剪枝策略 (Pruning Strategies)

### 核心思想

```
减少不必要的计算
只保留有希望的候选
加速搜索过程

两种剪枝:
1. 早期剪枝 (Early Pruning)
   - 分数太低的候选直接丢弃

2. 阈值剪枝 (Threshold Pruning)
   - 动态调整剪枝阈值
```

### 可视化示例

```
时间步 t=2 的候选扩展:
═══════════════════════

原始束搜索:
  候选1: "我 爱"    分数=-0.73
  候选2: "我 喜欢"  分数=-2.81
  候选3: "你 好"    分数=-2.59
  候选4: "你 在"    分数=-3.10
  候选5: "他 是"    分数=-4.50
  ... (总共 V 个候选)

每个候选扩展 V=10,000 个词:
  总计算量: 5 × 10,000 = 50,000 次

早期剪枝 (margin=2.0):
══════════════════════
  候选1: "我 爱"    分数=-0.73 ← 保留
  候选2: "我 喜欢"  分数=-2.81 ← 保留 (差值 2.08 < margin)
  候选3: "你 好"    分数=-2.59 ← 保留 (差值 1.86 < margin)
  候选4: "你 在"    分数=-3.10 ← 丢弃! (差值 2.37 > margin)
  候选5: "他 是"    分数=-4.50 ← 丢弃! (差值 3.77 > margin)
  ...

只保留 3 个候选:
  总计算量: 3 × 10,000 = 30,000 次
  加速: 50,000 → 30,000 (40% 加速!)
```

### 代码实现

```python
def beam_search_with_pruning(model, encoder_output,
                             beam_size=5, max_len=50,
                             margin=2.0, top_k=500):
    """
    带剪枝策略的束搜索

    参数:
        margin: 剪枝边距 (分数差值超过此值则剪枝)
        top_k: 每步只计算前 top_k 个词 (而非全部词汇表)
    """
    init_hidden = model.decoder.init_hidden(encoder_output)
    candidates = [([sos_id], 0.0, init_hidden)]

    finished = []

    for t in range(max_len):
        all_candidates = []

        # 找到当前最佳分数
        best_score = max(score for _, score, _ in candidates)
        threshold = best_score - margin

        for seq, score, hidden in candidates:
            # 剪枝: 分数过低的不扩展
            if score < threshold:
                continue

            last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
            output, new_hidden = model.decoder(
                last_word, hidden, encoder_output
            )

            # 只计算前 top_k 个词 (而非全部 V 个词)
            logits = output.squeeze(0).squeeze(0)
            top_logits, top_indices = torch.topk(logits, top_k)

            for log_prob, word_id in zip(top_logits, top_indices):
                new_seq = seq + [word_id.item()]
                new_score = score + log_prob.item()

                all_candidates.append(
                    (new_seq, new_score, new_hidden)
                )

        if not all_candidates:
            break

        all_candidates.sort(key=lambda x: x[1], reverse=True)
        candidates = all_candidates[:beam_size]

        if len(finished) >= beam_size:
            break

    finished.extend(candidates)
    finished.sort(key=lambda x: x[1], reverse=True)

    return finished[0][0], finished[0][1]
```

## 🎯 优化 5: 约束束搜索 (Constrained Beam Search)

### 应用场景

```
为什么需要约束?
══════════════

1. 术语翻译
   - 专有名词必须准确翻译
   - 专业术语不能随意替换

2. 关键词覆盖
   - 摘要必须包含某些关键词
   - 对话系统需要提及特定概念

3. 风格约束
   - 必须使用某些表达
   - 避免某些敏感词

4. 结构约束
   - 句法结构要求
   - 长度限制
```

### 核心思想

```
约束束搜索:
  - 维护约束状态 (哪些已满足)
  - 只有满足所有约束的序列才能完成
  - 优先扩展可能满足约束的候选
```

### 代码实现

```python
def constrained_beam_search(model, encoder_output,
                            constraints, beam_size=5):
    """
    约束束搜索

    参数:
        constraints: List[str] 必须包含的约束词
    """
    # 将约束词转换为 IDs
    constraint_ids = [vocab[word] for word in constraints]

    init_hidden = model.decoder.init_hidden(encoder_output)
    candidates = [
        ([sos_id], 0.0, init_hidden, set())  # (seq, score, hidden, satisfied_constraints)
    ]

    finished = []

    for t in range(max_len):
        all_candidates = []

        for seq, score, hidden, satisfied in candidates:
            if seq[-1] == eos_id:
                # 只有满足所有约束才能完成
                if len(satisfied) == len(constraint_ids):
                    finished.append((seq, score))
                continue

            last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
            output, new_hidden = model.decoder(
                last_word, hidden, encoder_output
            )

            log_probs = F.log_softmax(output.squeeze(0), dim=-1)

            # 优先考虑满足新约束的词
            for word_id in range(vocab_size):
                new_seq = seq + [word_id]
                new_satisfied = satisfied.copy()

                # 检查是否满足新约束
                if word_id in constraint_ids:
                    new_satisfied.add(word_id)

                log_prob = log_probs[word_id].item()
                new_score = score + log_prob

                # 如果已经结束但还有未满足的约束，则跳过
                if word_id == eos_id and len(new_satisfied) < len(constraint_ids):
                    continue

                all_candidates.append(
                    (new_seq, new_score, new_hidden, new_satisfied)
                )

        if not all_candidates:
            break

        # 优先排序: 已满足更多约束的候选
        all_candidates.sort(
            key=lambda x: (len(x[3]), x[1]),
            reverse=True
        )
        candidates = all_candidates[:beam_size]

    # 返回满足所有约束的最佳候选
    valid_finished = [c for c in finished if len(c[0]) > 2]  # 排除太短的序列
    if valid_finished:
        valid_finished.sort(key=lambda x: x[1], reverse=True)
        return valid_finished[0][0], valid_finished[0][1]
    else:
        # 如果没有候选满足约束，返回最佳候选
        finished.sort(key=lambda x: x[1], reverse=True)
        return finished[0][0], finished[0][1]
```

### 实践示例

```

候选1: "DeepSeek V3 是强大的模型"
  满足: DeepSeek ✓, V3 ✓
  可以结束: ✓

候选2: "这是一个强大的模型"
  满足: DeepSeek ✗, V3 ✗
  不可以结束: ✗

结果: 系统优先扩展可能包含约束词的候选
     最终找到满足所有约束的最佳序列
```

## 💡 核心要点总结

```
1. 五种优化技术
   ✅ 长度归一化 (Length Normalization)
      → 避免偏向短序列
      → α = 0.6-0.7 常用

   ✅ 覆盖惩罚 (Coverage Penalty)
      → 避免重复生成
      → β = 0.1-0.5 常用

   ✅ 温度采样 (Temperature Sampling)
      → 增加多样性
      → T = 0.7-1.0 平衡

   ✅ 剪枝策略 (Pruning)
      → 加速搜索
      → top_k = 500 加速 5×

   ✅ 约束搜索 (Constrained)
      → 满足特定需求
      → 术语、关键词覆盖

2. 超参数推荐
   ┌─────────────────┬──────────┬────────────┐
   │    参数         │  默认值  │   范围     │
   ├─────────────────┼──────────┼────────────┤
   │ beam_size       │    5     │   3-10     │
   │ α (长度归一化)  │   0.6    │  0.5-0.8   │
   │ β (覆盖惩罚)    │   0.2    │  0.1-0.5   │
   │ T (温度)        │   0.8    │  0.7-1.2   │
   │ top_k (剪枝)    │   500    │  200-1000  │
   │ margin (剪枝)   │   2.0    │  1.0-3.0   │
   └─────────────────┴──────────┴────────────┘

3. 组合使用建议
   机器翻译: α + β + top_k
   文本摘要: α + β + T + top_k
   对话生成: T + margin
   诗歌生成: α + T

4. 实践检查清单
   ✅ 是否偏向短序列? → 加长度归一化
   ✅ 是否生成重复? → 加覆盖惩罚
   ✅ 是否缺乏多样性? → 加温度采样
   ✅ 生成速度慢? → 加剪枝策略
   ✅ 有特定要求? → 加约束搜索
```

## 🤔 常见问题

```
Q1: 长度归一化 α 越大越好吗？
A1: 不是
    - α 过小: 仍然偏向短序列
    - α 过大: 可能偏向极长序列
    - 推荐: 0.6-0.7, 根据验证集调整

Q2: 所有优化都要一起用吗？
A2: 不一定
    - 先用基础优化: α + β + top_k
    - 根据具体需求添加: T (多样性) 或约束
    - 监控 BLEU 分数和质量变化

Q3: 温度采样 T 设为多少？
A3: 任务相关
    - T = 1.0: 原始分布
    - T < 1.0: 更确定 (保守)
    - T > 1.0: 更多样 (创新)
    - 推荐: T = 0.7-1.0 (平衡)

Q4: 剪枝会损失质量吗？
A4: 轻微损失换取大幅加速
    - top_k = 500: BLEU 几乎无损失
    - top_k = 100: 可能损失 0.2-0.5 BLEU
    - 推荐: top_k = 500 (速度与质量平衡)

Q5: 如何选择 beam_size？
A5: 任务相关
    - 翻译: k = 5-10
    - 摘要: k = 5-15
    - 对话: k = 1-5 (需要多样性)
    - 代码生成: k = 3-7 (需要精确)

Q6: 覆盖惩罚 β 如何调？
A6: 从小到大试
    - β = 0: 无惩罚
    - β = 0.1: 轻微惩罚
    - β = 0.5: 强惩罚
    - 推荐: β = 0.1-0.2, 观察重复率调整
```
