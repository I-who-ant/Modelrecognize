## 📌 基本定义

**序列生成 (Sequence Generation)** 是指给定源序列，生成目标序列的任务。核心问题是如何选择最优的输出序列。

### 问题背景

```
序列生成任务:
════════════

输入: 源序列 x = [x₁, x₂, ..., xₙ]
输出: 目标序列 y = [y₁, y₂, ..., yₘ]

示例:
────

机器翻译:
  输入: "I love you" (英文)
  输出: "我爱你" (中文)

文本摘要:
  输入: 长文章 (500词)
  输出: 摘要 (50词)

对话生成:
  输入: "你好吗？"
  输出: "我很好，谢谢！"

图像描述:
  输入: 图像
  输出: "一只猫坐在沙发上"

核心挑战:
════════

问题: 如何选择"最好的"输出序列？

假设词汇表大小 V = 10,000
目标序列长度 m = 10

可能的序列数量:
  V^m = 10,000^10 = 10^40

这是天文数字！
无法枚举所有可能的序列
→ 需要高效的搜索算法
```

## 🔄 编码器-解码器完整数据流详解

### 输入到编码器的过程

```
源序列输入: x = [x₁, x₂, x₃, ..., xₙ]
═══════════════════════════════════════

每个输入 token 首先经过嵌入层:
  x₁ → Embedding(x₁) = e₁ ∈ ℝ^d_model
  x₂ → Embedding(x₂) = e₂ ∈ ℝ^d_model
  x₃ → Embedding(x₃) = e₃ ∈ ℝ^d_model
  ...
  xₙ → Embedding(xₙ) = eₙ ∈ ℝ^d_model

嵌入向量序列: E = [e₁, e₂, e₃, ..., eₙ] ∈ ℝ^(n × d_model)

编码器处理:
  E → [RNN/LSTM/Transformer Encoder] → H = [h₁, h₂, h₃, ..., hₙ]

编码器输出: H = [h₁, h₂, h₃, ..., hₙ]
  其中 hᵢ ∈ ℝ^d_hidden 是第 i 个位置的隐藏状态
  hᵢ 包含了前 i 个 tokens 的上下文信息
```

### 编码器到解码器的向量传递

```
方式 1: 最后一个隐藏状态作为上下文
═══════════════════════════════════════

如果使用简单 RNN/LSTM:
  hₙ (最后一个隐藏状态) → 作为上下文向量 c

  c = hₙ ∈ ℝ^d_hidden
简单 Seq2Seq 模型使用固定的上下文向量 c
在解码的每一步，都使用相同的上下文向量
```
  c 包含了整个源序列的信息

```
解码器初始状态:
══════════════

s₀ = tanh(W_s · c + b_s)  (初始化隐藏状态)
其中 c 是编码器的上下文向量

每个时间步的计算:
═══════════════

时间步 t = 1:
  输入: y₀ (<SOS> token 的嵌入)
  计算: s₁ = RNN(s₀, y₀)
  输出: o₁ = W_o · s₁ + b_o
  概率: P₁ = softmax(o₁) ∈ ℝ^V
  选择: y₁ = argmax(P₁) 或通过束搜索选择

时间步 t = 2:
  输入: y₁ (上一步选择的 token 的嵌入)
  计算: s₂ = RNN(s₁, y₁)
  输出: o₂ = W_o · s₂ + b_o
  概率: P₂ = softmax(o₂) ∈ ℝ^V
  选择: y₂ = argmax(P₂) 或通过束搜索选择

...

时间步 t = m:
  输入: yₘ₋₁
  计算: sₘ = RNN(sₘ₋₁, yₘ₋₁)
  输出: oₘ = W_o · sₘ + b_o
  概率: Pₘ = softmax(oₘ) ∈ ℝ^V
  如果 Pₘ[<EOS>] > 阈值，停止生成


  = P(y₁ | x) × P(y₂ | x, y₁) × ... × P(yₘ | x, y₁, ..., yₘ₋₁)
完整概率计算公式:
═══════════════

在时间步 t:
  给定源序列 x 和已生成的历史 y₁, y₂, ..., yₜ₋₁
  计算下一个 token 的概率分布:

  P(yₜ | y₁, ..., yₜ₋₁, x) = softmax(W_o · sₜ)

  其中:
    sₜ = RNN(sₜ₋₁, yₜ₋₁, c)
    
    c 是编码器生成的固定上下文向量（不随时间变化）



实际计算流程:
═══════════

输入: "I love you" → "我爱你"

步骤 1 (t=1):
  ┌────────────────────────────────────────┐
  │ 输入: <SOS>                            │
  │ 嵌入: e₀ = Embedding(<SOS>)            │
  │ 隐藏: s₁ = RNN(s₀, e₀)                 │
  │ 输出: o₁ = W_o · s₁                    │
  │ 概率: P₁ = softmax(o₁)                 │
  │     P₁ = [P(我)=0.6, P(你)=0.1, ...]   │
  │ 选择: y₁ = "我" (argmax)               │
  └────────────────────────────────────────┘

步骤 2 (t=2):
  ┌────────────────────────────────────────┐
  │ 输入: "我"                             │
  │ 嵌入: e₁ = Embedding("我")             │
  │ 隐藏: s₂ = RNN(s₁, e₁)                 │
  │ 输出: o₂ = W_o · s₂                    │
  │ 概率: P₂ = softmax(o₂)                 │
  │     P₂ = [P(爱)=0.8, P(喜欢)=0.1, ...] │
  │ 选择: y₂ = "爱" (argmax)               │
  └────────────────────────────────────────┘

步骤 3 (t=3):
  ┌────────────────────────────────────────┐

  │ 嵌入: e₂ = Embedding("爱")             │
  │ 隐藏: s₃ = RNN(s₂, e₂)                 │
  │ 输出: o₃ = W_o · s₃                    │

  │ 选择: y₃ = "你" (argmax)               │
  └────────────────────────────────────────┘

步骤 4 (t=4):
  ┌────────────────────────────────────────┐
  │ 输入: "你"                             │
  │ 嵌入: e₃ = Embedding("你")             │

  │ 输出: o₄ = W_o · s₄                    │
  │ 概率: P₄ = softmax(o₄)                 │
  │     P₄ = [P(<EOS>)=0.9, ...]           │
  │ 选择: y₄ = "<EOS>" (argmax)            │
  └────────────────────────────────────────┘

完成: 输出序列 y = ["我", "爱", "你"]

## 🔢 为什么要使用对数概率？

### 核心问题

```
束搜索的目标是找到概率最大的序列:
  y* = argmax P(y | x)
       y

其中:
  P(y | x) = P(y₁, y₂, ..., yₘ | x)
           = P(y₁|x) × P(y₂|x,y₁) × ... × P(yₘ|x,y₁,...,yₘ₋₁)

⚠️ 问题: 直接计算 P(y | x) 会导致数值下溢！
```

### 数值下溢演示

```
示例: 计算 P("我爱你" | "I love you")

P("我爱你" | "I love you")
  = P("我") × P("爱"|"我") × P("你"|"我爱") × P("<EOS>"|"我爱你")
  = 0.6 × 0.8 × 0.7 × 0.9
  = 0.3024  ✓ 可以计算

但是长序列呢?
P("我非常非常爱你" | "I love you")
  = 0.6 × 0.4 × 0.3 × 0.2 × 0.8 × 0.7 × 0.9
  = 0.00607  ✓ 还可以

当序列长度 m = 20:
  P ≈ 10^(-15) 到 10^(-30)
  → 计算机的浮点数精度不够!
  → 结果会被舍入为 0 (数值下溢) ❌
```

### 解决方案：对数概率

```
数学性质:
  log(a × b) = log(a) + log(b)

因此:
  log P(y | x)
    = log [P(y₁|x) × P(y₂|x,y₁) × ... × P(yₘ|x,y₁,...,yₘ₋₁)]
    = log P(y₁|x) + log P(y₂|x,y₁) + ... + log P(yₘ|x,y₁,...,yₘ₋₁)
    = Σᵢ log P(yᵢ | x, y₁, ..., yᵢ₋₁)

束搜索实际使用:
  score = Σᵢ log P(yᵢ | x, y<ᵢ)
```

### 可视化对比

```
直接使用概率 (❌):
  P("我爱你") = 0.6 × 0.8 × 0.7 × 0.9 = 0.3024
  P("我非常爱你") = 0.6 × 0.4 × 0.3 × 0.2 × 0.8 × 0.7 × 0.9 = 0.00607
  P(长序列20词) ≈ 10^(-25) → 下溢为 0!

使用对数概率 (✅):
  log P("我爱你") = -0.51 + (-0.22) + (-0.36) + (-0.11) = -1.20
  log P("我非常爱你") = -5.93
  log P(长序列20词) = -57.3 (仍然是有限数值!)
```

### 代码实现

```python
# ❌ 错误: 直接使用概率 (会下溢)

    """计算序列概率"""
    prob = 1.0

    """计算序列对数概率"""
    log_prob = 0.0
    for log_p in words_log_probs:

### 关键要点

```
✅ 使用 log P 的原因:
  1. 避免数值下溢 (连乘 → 相加)
  2. 计算机更精确处理有限数值
  3. 便于比较和排序 (都是有限数值)
  4. 数值计算更稳定

⚠️ 注意事项:
  - log P 总是负数 (因为 0 < P < 1)
  - 分数越接近 0 = 概率越大
  - 分数越负 = 概率越小
  - 最终可转换回概率: P = exp(log P)
```

## 🎯 基础序列生成模型 (Seq2Seq)

### Encoder-Decoder 架构

```
基本架构:
════════

编码器 (Encoder):
  将源序列编码为固定长度的上下文向量

  输入: x = [x₁, x₂, ..., xₙ]
    ↓
  [RNN/LSTM/GRU]
    ↓
  输出: 上下文向量 c ∈ ℝ^d
       (通常是最后的隐藏状态)
    
解码器 (Decoder):
  根据上下文向量逐步生成目标序列

  输入: 上下文 c
    ↓
  [RNN/LSTM/GRU]
    ↓
  输出: y = [y₁, y₂, ..., yₘ]

完整流程:
════════

           Encoder                  Decoder
           ────────                ────────
  x₁  x₂  x₃  <EOS>              <SOS> y₁  y₂  y₃ <EOS>
   ↓   ↓   ↓   ↓                   ↓    ↓   ↓   ↓   ↓
  [h₁][h₂][h₃][h₄]               [s₀][s₁][s₂][s₃][s₄]
                ↓                   ↑    ↓   ↓   ↓   ↓
           上下文 c ────────────────┘    P₁  P₂  P₃  P₄
                                        ↓   ↓   ↓   ↓
                                        y₁  y₂  y₃ <EOS>

示例 (机器翻译):
───────────────

输入: "I love you"

Encoder:
  I    → h₁
  love → h₂
  you  → h₃
  <EOS>→ h₄ = c (上下文向量)

Decoder:
  s₀ = f(c)           (初始状态)
  s₁ = f(s₀, <SOS>)   (从开始符号开始)
  P₁ = softmax(W·s₁)  (第一个词的概率分布)
  y₁ = argmax(P₁) = "我"

  s₂ = f(s₁, y₁)      (基于前一个词)
  P₂ = softmax(W·s₂)
  y₂ = argmax(P₂) = "爱"

  s₃ = f(s₂, y₂)
  P₃ = softmax(W·s₃)
  y₃ = argmax(P₃) = "你"

  s₄ = f(s₃, y₃)
  P₄ = softmax(W·s₄)
  y₄ = argmax(P₄) = "<EOS>"

输出: "我爱你"
```

### 概率建模

```
数学表达:
════════

目标: 找到概率最大的输出序列

P(y | x) = P(y₁, y₂, ..., yₘ | x)

根据链式法则:
  P(y | x) = P(y₁|x) · P(y₂|x,y₁) · P(y₃|x,y₁,y₂) · ... · P(yₘ|x,y₁,...,yₘ₋₁)

           = ∏ᵢ₌₁ᵐ P(yᵢ | x, y₁, ..., yᵢ₋₁)

我们的目标:
  y* = argmax P(y | x)
       y

   = argmax ∏ᵢ₌₁ᵐ P(yᵢ | x, y₁, ..., yᵢ₋₁)
       y

   = argmax Σᵢ₌₁ᵐ log P(yᵢ | x, y₁, ..., yᵢ₋₁)  (取对数)
       y

示例:
────

假设生成 "我爱你":

P(我爱你 | "I love you")
  = P(我 | <SOS>, c)
    × P(爱 | <SOS>, 我, c)
    × P(你 | <SOS>, 我, 爱, c)
    × P(<EOS> | <SOS>, 我, 爱, 你, c)

  = 0.6 × 0.8 × 0.7 × 0.9
  = 0.3024

log P = log(0.6) + log(0.8) + log(0.7) + log(0.9)
      = -0.51 + (-0.22) + (-0.36) + (-0.11)
      = -1.20
```

## 🔍 选择最可能句子：解码策略

### 策略 1: 贪心搜索 (Greedy Search)

```
核心思想:
════════

每一步选择概率最高的词
不考虑全局最优性

算法流程:
════════

1. 初始化: y₀ = <SOS>
2. 对于 t = 1, 2, ..., T:
   a. 计算概率分布: P(· | x, y₁, ..., yₜ₋₁)
   b. 选择最大概率: yₜ = argmax P(w | x, y₁, ..., yₜ₋₁)
                          w∈V
   c. 如果 yₜ = <EOS>, 停止
3. 输出: y = [y₁, y₂, ..., yₜ]

伪代码:
──────

```python
def greedy_search(encoder_output, decoder, max_len=50):
    """贪心搜索解码"""
    # 初始化
    y = [<SOS>]
    hidden = decoder.init_hidden(encoder_output)

    for t in range(max_len):
        # 计算概率分布
        probs, hidden = decoder(y[-1], hidden)
        # probs: [vocab_size]

        # 选择概率最高的词
        next_word = torch.argmax(probs)

        # 添加到序列
        y.append(next_word)

        # 如果生成结束符,停止
        if next_word == <EOS>:
            break

    return y
```

示例:
────

机器翻译: "I love you" → ?

步骤 1:
  输入: <SOS>
  P("我") = 0.6  ← 最高
  P("你") = 0.1
  P("爱") = 0.2
  P("他") = 0.1
  选择: "我"

步骤 2:
  输入: 我
  P("爱") = 0.8  ← 最高
  P("喜欢") = 0.1
  P("恨") = 0.05
  P("看") = 0.05
  选择: "爱"

步骤 3:
  输入: 我 爱
  P("你") = 0.7  ← 最高
  P("他") = 0.2
  P("她") = 0.1
  选择: "你"

步骤 4:
  输入: 我 爱 你
  P(<EOS>) = 0.9  ← 最高
  选择: <EOS>

输出: "我爱你"

优点:
────

✅ 简单快速
✅ 每步只需要 O(V) 计算
✅ 总复杂度 O(T × V)
✅ 内存占用小

缺点:
────

❌ 局部最优 ≠ 全局最优
❌ 无法回溯
❌ 容易陷入次优解

问题示例:
────────

贪心搜索可能生成:
  "我 非常 爱 你"
  log P = -0.5 + (-1.2) + (-0.3) + (-0.1) = -2.1

但全局最优是:
  "我 爱 你"
  log P = -0.6 + (-0.2) + (-0.1) = -0.9  ← 更好！

原因:
  第一步选择 "非常" (P=0.7) 比 "爱" (P=0.6) 概率高
  但导致后续概率降低
  总体概率反而更低
```

### 策略 2: 穷举搜索 (Exhaustive Search)

```
核心思想:
════════

枚举所有可能的序列
选择概率最高的

算法:
════

对所有长度为 m 的序列 y:
  计算 P(y | x)
选择: y* = argmax P(y | x)
              y

复杂度:
──────

假设:
  词汇表大小 V = 10,000
  序列长度 m = 10

需要评估的序列数:
  V^m = 10,000^10 = 10^40

即使每秒评估 10^9 个序列
需要时间:
  10^40 / 10^9 = 10^31 秒
            = 3.17 × 10^23 年
            = 宇宙年龄的 10^13 倍 !!!

结论:
  ❌ 完全不可行
  ❌ 即使量子计算机也无法完成
```

## ⚡ 束搜索 (Beam Search)

### 编码器-解码器在束搜索中的完整流程

```
束搜索的完整工作流程:
════════════════════

输入: 源序列 x = [x₁, x₂, ..., xₙ]
输出: 最佳目标序列 y = [y₁, y₂, ..., yₘ]


阶段 1: 编码器处理 (一次性完成)
═══════════════════════════════

步骤 1.1: 嵌入层转换
  输入: x = [x₁, x₂, x₃, ..., xₙ]
    ↓
  x₁ → Embedding(x₁) = e₁ ∈ ℝ^d_model
  x₂ → Embedding(x₂) = e₂ ∈ ℝ^d_model
  ...
  xₙ → Embedding(xₙ) = eₙ ∈ ℝ^d_model
  
  输出: E = [e₁, e₂, ..., eₙ] ∈ ℝ^(n × d_model)

步骤 1.2: 编码器前向传播
  输入: E = [e₁, e₂, ..., eₙ]
    ↓
  [RNN/LSTM 编码器]
    ↓
  隐藏状态: H = [h₁, h₂, h₃, ..., hₙ]
    其中 hᵢ 包含前 i 个 tokens 的信息

步骤 1.3: 生成上下文向量
  取最后一个隐藏状态: c = hₙ
    ↓
  上下文向量 c ∈ ℝ^d_hidden
  (这个 c 将传递给解码器，在整个生成过程中保持不变)

输出阶段1: 
  ✅ 固定上下文向量 c (用于所有解码步骤)
  ✅ 初始隐藏状态 s₀ = tanh(W_s · c + b_s)


阶段 2: 束搜索解码 (逐步生成)
════════════════════════════

与贪心搜索不同，束搜索维护 k 个候选序列
每个候选有: (序列, 累积对数概率, 当前隐藏状态)

时间步 t = 1:
───────────

输入: 初始状态 (s₀, c)
候选: 所有候选从 <SOS> 开始

┌─────────────────────────────────────────────┐
│ 步骤 2.1: 解码器计算                         │
│ 1. 对每个候选 (共k个):                      │
│    输入: <SOS> 嵌入                          │
│    计算: s₁ = RNN(s₀, Embed(<SOS>))        │
│    输出: o₁ = W_o · s₁ + b_o               │
│    概率: P₁ = softmax(o₁) ∈ ℝ^V            │
│                                             │
│ 2. 每个候选考虑所有 V 个词:                  │
│    新候选 = [w₁, w₂, ..., w_V]              │
│    新分数 = log P(wᵢ | <SOS>, c)           │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 步骤 2.2: 束搜索选择                         │
│ 从所有 k × V 个候选中选择 top-k:             │
│                                             │
│ 候选1: (<SOS>, w₁)   分数 = -0.51          │
│ 候选2: (<SOS>, w₂)   分数 = -0.73          │
│ ...                                         │
│ 候选k: (<SOS>, wₖ)   分数 = -1.20          │
│                                             │
│ 这 k 个候选进入下一步解码                    │
└─────────────────────────────────────────────┘

输出 t=1: k 个候选序列 [(<SOS>, w₁), (<SOS>, w₂), ..., (<SOS>, wₖ)]


时间步 t = 2:
───────────

输入: k 个候选 + (s₀, c)

┌─────────────────────────────────────────────┐
│ 步骤 2.1: 解码器计算                         │
│ 1. 对每个候选 (共k个):                      │
│    例如候选1: [w₁]                          │
│    输入: w₁ 的嵌入                          │
│    计算: s₂ = RNN(s₁, Embed(w₁))          │
│    输出: o₂ = W_o · s₂ + b_o               │
│    概率: P₂ = softmax(o₂) ∈ ℝ^V            │
│                                             │
│ 2. 每个候选考虑所有 V 个词:                  │
│    新候选1: [w₁, w₁']                       │
│    新候选2: [w₁, w₂']                       │
│    ...                                      │
│    新候选V: [w₁, w_V']                      │
│                                             │
│ 对所有 k 个候选重复上述过程                  │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 步骤 2.2: 累积分数                          │
│ 分数累积规则:                              │
│  total_score = 之前的分数 + log P(wᵢ | ...) │
│                                             │
│ 示例:                                       │
│ 候选1: -0.51 + log P(w₁' | w₁) = -0.73     │
│ 候选2: -0.51 + log P(w₂' | w₁) = -1.10     │
│ ...                                         │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 步骤 2.3: 束搜索选择                         │
│ 从所有 k × V 个候选中选择 top-k:             │
│                                             │
│ 候选1: [w₁, w₁']  分数 = -0.73             │
│ 候选2: [w₁, w₂']  分数 = -0.85             │
│ 候选3: [w₂, w₁']  分数 = -0.90             │
│ ...                                         │
│ 候选k: [wₖ, wₖ']  分数 = -1.50             │
│                                             │
│ 这 k 个候选进入下一步解码                    │
└─────────────────────────────────────────────┘

输出 t=2: k 个候选序列


时间步 t = 3, 4, ..., m:
───────────────────────

重复步骤 2.1-2.3:
  - 每个候选扩展 V 个选择
  - 计算累积对数概率
  - 从 k×V 个候选中选择 top-k

直到所有候选都生成 <EOS> 或达到最大长度


阶段 3: 输出最佳序列
═══════════════════

当搜索结束或所有候选完成时:
  从所有完成的候选中选择分数最高的序列

输出: y* = argmax (累积对数概率)


完整示例 (k=2, 翻译 "I love you"):
══════════════════════════════

编码器阶段 (t=0):
────────────────
输入: "I love you" → [I, love, you, <EOS>]
编码: h₁, h₂, h₃, h₄
上下文: c = h₄
初始: s₀ = tanh(W_s · c + b_s)

束搜索解码:
──────────

t=1: 生成第一个词
  候选1: [<SOS>, 我]     分数=-0.51  ← 选择
  候选2: [<SOS>, 你]     分数=-1.90  ← 选择
  (其他候选被剪枝)

t=2: 生成第二个词
  候选1扩展:
    [<SOS>, 我, 爱]    分数=-0.73  ← 选择
    [<SOS>, 我, 喜欢]  分数=-2.81
  候选2扩展:
    [<SOS>, 你, 好]    分数=-2.59  ← 选择
    [<SOS>, 你, 在]    分数=-3.10

t=3: 生成第三个词
  候选1扩展:
    [<SOS>, 我, 爱, 你]    分数=-1.09  ← 选择
    [<SOS>, 我, 爱, 他]    分数=-2.34
  候选2扩展:
    [<SOS>, 你, 好, 吗]    分数=-3.10
    [<SOS>, 你, 好, 啊]    分数=-3.79

t=4: 生成结束符
  候选1: [<SOS>, 我, 爱, 你, <EOS>]  分数=-1.20  ← 完成!
  候选2: [<SOS>, 我, 爱, 他, <EOS>]  分数=-2.70  ← 完成!

最终输出: "我 爱 你" (分数=-1.20)


关键特点总结:
═══════════

1. 编码器只运行一次 (t=0)，生成固定的上下文向量
2. 解码器运行 T 次 (T = 输出长度)
3. 每步束搜索维护 k 个候选
4. 每个候选有独立的隐藏状态
5. 分数是累积对数概率 (避免数值下溢)
6. 剪枝策略: 每步只保留 top-k 个最佳候选
7. 解码质量 vs 计算复杂度的权衡
```

### 核心思想

```
折中方案:
════════

不是每步只保留 1 个候选 (贪心)
也不是保留所有候选 (穷举)
而是保留 k 个最佳候选 (束搜索)

k = beam size (束宽)

示例:
────

k = 1: 贪心搜索
k = V: 穷举搜索 (理论上)
k = 3-10: 实践中常用

权衡:
  k ↑ → 更接近全局最优 → 计算量 ↑
  k ↓ → 更快 → 可能陷入局部最优
```

### 算法流程

```
Beam Search 算法:
═════════════════

参数:
  k: beam size (束宽)
  V: 词汇表大小
  T: 最大生成长度

步骤:
════

步骤 0: 初始化
  candidates = [(<SOS>,)]  (1个候选)
  scores = [0.0]           (对数概率)

步骤 1: 扩展第一个词
  对每个候选 c 和每个词 w ∈ V:
    新候选 c' = c + (w,)
    新分数 s' = s + log P(w | x, c)

  保留前 k 个:
    candidates = top_k(所有新候选, k)

步骤 2, 3, ..., T: 重复扩展
  对每个候选 c 和每个词 w ∈ V:
    新候选 c' = c + (w,)
    新分数 s' = s + log P(w | x, c)

  保留前 k 个:
    candidates = top_k(所有新候选, k)

  如果所有候选都以 <EOS> 结束,停止

步骤 T+1: 输出
  从 candidates 中选择分数最高的序列

### 完整实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from typing import List, Tuple

class BeamSearch:
    """束搜索解码器"""

    def __init__(self, model, beam_size=3, max_len=50,
                 sos_id=1, eos_id=2):
        """
        参数:
            model: Seq2Seq 模型
            beam_size: 束宽
            max_len: 最大生成长度
            sos_id: 开始符号 ID
            eos_id: 结束符号 ID
        """
        self.model = model
        self.beam_size = beam_size
        self.max_len = max_len
        self.sos_id = sos_id
        self.eos_id = eos_id

    def search(self, encoder_output):
        """
        束搜索解码

        参数:
            encoder_output: 编码器输出 [batch_size=1, seq_len, hidden_size]

        返回:
            best_sequence: 最佳序列 [seq_len]
            best_score: 最佳分数 (对数概率)
        """
        batch_size = encoder_output.size(0)
        assert batch_size == 1, "束搜索当前只支持 batch_size=1"

        # 初始化
        # candidates: List[(sequence, score, hidden)]
        # sequence: List[int] - 词 ID 序列
        # score: float - 累积对数概率
        # hidden: tensor - 解码器隐藏状态

        init_hidden = self.model.decoder.init_hidden(encoder_output)
        candidates = [
            ([self.sos_id], 0.0, init_hidden)
        ]

        finished = []  # 已完成的序列

        for t in range(self.max_len):
            all_candidates = []

            # 扩展每个候选
            for seq, score, hidden in candidates:
                # 如果已经结束,不再扩展
                if seq[-1] == self.eos_id:
                    finished.append((seq, score))
                    continue

                # 获取最后一个词
                last_word = torch.LongTensor([seq[-1]]).unsqueeze(0)
                # last_word: [batch=1, seq_len=1]

                # 解码一步
                output, new_hidden = self.model.decoder(
                    last_word, hidden, encoder_output
                )
                # output: [batch=1, seq_len=1, vocab_size]

                # 计算对数概率
                log_probs = F.log_softmax(output.squeeze(0).squeeze(0), dim=0)
                # log_probs: [vocab_size]

                # 获取前 beam_size 个词
                top_log_probs, top_indices = torch.topk(
                    log_probs, self.beam_size
                )

                # 创建新候选
                for log_prob, word_id in zip(top_log_probs, top_indices):
                    new_seq = seq + [word_id.item()]
                    new_score = score + log_prob.item()
                    all_candidates.append(
                        (new_seq, new_score, new_hidden)
                    )

            # 如果没有新候选(所有序列都已结束)
            if not all_candidates:
                break

            # 选择前 beam_size 个候选
            # 按分数排序(降序)
            all_candidates.sort(key=lambda x: x[1], reverse=True)
            candidates = all_candidates[:self.beam_size]

            # 早停: 如果已有足够的完成序列
            if len(finished) >= self.beam_size:
                break

        # 将未完成的候选也加入
        finished.extend(candidates)

        # 选择最佳序列
        finished.sort(key=lambda x: x[1], reverse=True)
        best_seq, best_score = finished[0]

        return best_seq, best_score


# ═══════════════════════════════════════════════════════
# 使用示例
# ═══════════════════════════════════════════════════════

class Seq2SeqModel(nn.Module):
    """简化的 Seq2Seq 模型"""
    def __init__(self, vocab_size, embed_size, hidden_size):
        super().__init__()
        self.encoder = Encoder(vocab_size, embed_size, hidden_size)
        self.decoder = Decoder(vocab_size, embed_size, hidden_size)

    def forward(self, src, tgt):
        encoder_output, hidden = self.encoder(src)
        decoder_output, _ = self.decoder(tgt, hidden, encoder_output)
        return decoder_output


# 创建模型
model = Seq2SeqModel(vocab_size=10000, embed_size=256, hidden_size=512)

# 创建束搜索解码器
beam_search = BeamSearch(
    model,
    beam_size=5,
    max_len=50,
    sos_id=1,
    eos_id=2
)

# 编码输入
src = torch.LongTensor([[3, 145, 67, 2]])  # "I love you <EOS>"
encoder_output, _ = model.encoder(src)

# 束搜索解码
best_seq, best_score = beam_search.search(encoder_output)

print(f"最佳序列: {best_seq}")
print(f"对数概率: {best_score:.4f}")
print(f"概率: {torch.exp(torch.tensor(best_score)):.4f}")

## 📊 复杂度分析

```
贪心搜索:
════════

时间复杂度:
  每步: O(V)  (计算所有词的概率)
  总共: O(T × V)

空间复杂度:
  O(1)  (只保留当前候选)

束搜索:
══════

时间复杂度:
  每步: O(k × V)  (扩展 k 个候选,每个考虑 V 个词)
  选择: O(k × V × log(k × V))  (排序)
  总共: O(T × k × V × log(k × V))

空间复杂度:
  O(k × T)  (保留 k 个长度为 T 的候选)

实践优化:
════════

不需要计算所有 V 个词:
  只计算前 top-p 个最可能的词
  top-p = 100-1000 (远小于 V=10,000-50,000)

优化后:
  时间: O(T × k × p × log(k × p))
  p << V → 显著加速

示例:
  V = 50,000
  k = 5
  p = 500
  T = 30

  原始: 30 × 5 × 50,000 = 7,500,000 次计算
  优化: 30 × 5 × 500 = 75,000 次计算
  加速 100 倍！
```

    - 但有时贪心更快且足够好
    - 实时系统可能优先贪心

Q2: beam_size 越大越好吗？
A2: 不是
    - k ↑ → 质量 ↑ 但收益递减
    - k ↑ → 计算 ↑ 线性增长
    - 实践: k=5-10 通常最佳

Q3: 为什么不用最大化 P(y|x) 而用 log P?
A3: 数值稳定性
    - P(y|x) = ∏ P(yᵢ|...) → 连乘很小的数 → 下溢
    - log P(y|x) = Σ log P(yᵢ|...) → 求和 → 稳定

Q4: 束搜索能保证全局最优吗？
A4: ❌ 不能
    - 仍然是启发式搜索
    - 但比贪心更接近最优
    - 实践中效果很好

Q5: 如何处理不同长度的候选？
A5: 长度归一化
    - score / length^α
    - 或使用 Google 的公式
