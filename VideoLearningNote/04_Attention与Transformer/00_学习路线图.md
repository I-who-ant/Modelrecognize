#### **33. 自注意力机制（Self-Attention）** ⭐⭐⭐⭐⭐ **最核心！**
```
核心问题: Self-Attention 是如何工作的？
学习要点:
  ├─ Self-Attention 的直观理解
  │   └─ 每个词都看其他所有词
  ├─ Q, K, V 的计算
  │   ├─ Q = X · W_Q  (查询: 我想找什么)
  │   ├─ K = X · W_K  (键: 我提供什么信息)
  │   └─ V = X · W_V  (值: 我的实际内容)
  ├─ Attention 分数计算
  │   ├─ Score = Q · K^T  (相似度矩阵)
  │   ├─ Scaled: Score / √d_k  (缩放避免梯度消失)
  │   └─ Weights = softmax(Score)  (归一化)
  ├─ 输出计算
  │   └─ Output = Weights · V  (加权求和)
  ├─ 完整公式
  │   └─ Attention(Q,K,V) = softmax(QK^T / √d_k) V
  ├─ 矩阵形式的维度分析
  │   ├─ X: [seq_len, d_model]
  │   ├─ Q, K, V: [seq_len, d_k]
  │   ├─ Attention Weights: [seq_len, seq_len]
  │   └─ Output: [seq_len, d_k]
  └─ 可视化理解
      └─ Attention 权重矩阵的含义

数学推导: 完整的 Self-Attention 公式推导
代码实现: 从零实现 Self-Attention
类比:
  - Q: "我想找什么" (问题)
  - K: "我是什么" (标签)
  - V: "我的内容" (答案)
  - 就像搜索引擎: Query → 匹配 Key → 返回 Value

关键理解:
  1. 为什么要分 Q, K, V 三个矩阵？
  2. 为什么要 Scale by √d_k？
  3. Self-Attention 的并行化优势
  4. 与传统 Attention 的区别

时间: 4-6小时（重点学习，反复练习）
```

### 🎨 **Phase 3: Multi-Head Attention**

#### **34. 多头注意力（Multi-Head Attention）** ⭐⭐⭐⭐⭐
```
核心问题: 为什么需要多个注意力头？
学习要点:
  ├─ 单个 Attention Head 的局限
  │   └─ 只能学习一种模式
  ├─ Multi-Head 的动机
  │   ├─ 不同 head 关注不同模式
  │   ├─ 语法、语义、位置等
  │   └─ 集成学习效果
  ├─ 多头的计算过程
  │   ├─ 每个 head 独立计算 Attention
  │   │   head_i = Attention(Q·W_i^Q, K·W_i^K, V·W_i^V)
  │   ├─ 拼接所有 head
  │   │   MultiHead = Concat(head_1, head_2, ..., head_h)
  │   └─ 线性变换输出
  │       Output = MultiHead · W^O
  ├─ 参数维度分析
  │   ├─ h: head 数量（通常 8-16）
  │   ├─ d_k = d_model / h  (每个 head 的维度)
  │   ├─ W_i^Q, W_i^K, W_i^V: [d_model, d_k]
  │   └─ W^O: [d_model, d_model]
  ├─ 计算复杂度
  │   └─ O(n² · d_model)  (与单头相同)
  └─ 可视化不同 head 的注意力模式

实践:
  - 实现 Multi-Head Attention
  - 可视化不同 head 的关注点
  - 理解为什么 8-16 个 head 是常见选择

与 DeepSeek-V3 的关系:
  └─ MLA (Multi-Head Latent Attention) 是多头的改进
      ├─ 压缩 KV cache
      ├─ 减少内存和计算
      └─ 保持多头的表达能力

类比: 多个人从不同角度看同一件事
时间: 3-4小时
```

### 🏗️ **Phase 4: Transformer 完整架构**

#### **35. Transformer 网络架构** ⭐⭐⭐⭐⭐
```
核心问题: 完整的 Transformer 是如何组合的？
学习要点:
  ├─ 整体架构
  │   ├─ Encoder (左侧)
  │   ├─ Decoder (右侧)
  │   └─ Encoder-Decoder Attention (连接)
  │
  ├─ Encoder 结构 (重复 N 层)
  │   ├─ Multi-Head Self-Attention
  │   ├─ Add & Norm (残差 + Layer Norm)
  │   ├─ Feed-Forward Network
  │   └─ Add & Norm
  │
  ├─ Decoder 结构 (重复 N 层)
  │   ├─ Masked Multi-Head Self-Attention
  │   ├─ Add & Norm
  │   ├─ Cross-Attention (连接 Encoder)
  │   ├─ Add & Norm
  │   ├─ Feed-Forward Network
  │   └─ Add & Norm
  │
  ├─ Position Encoding (位置编码)
  │   ├─ 为什么需要位置信息
  │   ├─ Sinusoidal Position Encoding
  │   │   ├─ PE(pos, 2i) = sin(pos / 10000^(2i/d))
  │   │   └─ PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
  │   └─ Learned Position Embedding
  │
  ├─ Feed-Forward Network (FFN)
  │   ├─ 两层全连接: FFN(x) = max(0, xW₁+b₁)W₂+b₂
  │   ├─ Position-wise (每个位置独立)
  │   ├─ 维度: d_model → d_ff (通常 4x) → d_model
  │   └─ 作用: 非线性变换，增加模型容量
  │
  ├─ Layer Normalization
  │   ├─ LN(x) = γ · (x - μ) / √(σ² + ε) + β
  │   ├─ Pre-LN vs Post-LN
  │   └─ RMSNorm (DeepSeek-V3 使用)
  │
  ├─ Residual Connection (残差连接)
  │   ├─ y = x + Sublayer(x)
  │   ├─ 缓解梯度消失
  │   └─ 便于深层网络训练
  │
  ├─ Masking 机制
  │   ├─ Padding Mask (屏蔽 padding)
  │   ├─ Look-ahead Mask (Decoder 自回归)
  │   └─ 为什么 Decoder 需要 Masking
  │
  └─ 完整的前向传播流程
      ├─ 输入 Embedding + Position Encoding
      ├─ Encoder 处理
      ├─ Decoder 自回归生成
      └─ 输出 Softmax 预测

代码实现:
  - 从零实现完整的 Transformer
  - 理解每个组件的作用
  - 调试和可视化

关键理解:
  1. 为什么需要 Position Encoding？
  2. 残差连接的重要性
  3. Layer Norm 的作用和位置
  4. FFN 的 position-wise 含义
  5. Encoder vs Decoder 的区别
  6. Masked Attention 的必要性

时间: 6-8小时（最重要的部分）
```

```

  ├─ Pre-LN vs Post-LN
  │   ├─ Post-LN: 原始 Transformer
  │   ├─ Pre-LN: 现代标准，训练更稳定
```

#### **Attention 优化技术** ⭐⭐⭐
```
核心问题: 如何优化 Attention 的计算和内存？
学习要点:
  ├─ Flash Attention
  │   ├─ GPU 内存优化
  │   ├─ 减少 HBM 访问
  │   └─ 加速 2-3 倍
  ├─ Multi-Query Attention (MQA)
  │   ├─ 所有 head 共享 K, V
  │   ├─ 减少 KV cache
  │   └─ 推理加速
  ├─ Grouped-Query Attention (GQA)
  │   ├─ MHA 和 MQA 的折中
  │   ├─ 部分 head 共享 K, V
  │   └─ 平衡性能和效率
  └─ Multi-Head Latent Attention (MLA) ⭐⭐⭐⭐⭐
      ├─ DeepSeek-V3 的核心创新！
      ├─ 将 K, V 压缩到低维 latent space
      ├─ 大幅减少 KV cache
      │   └─ 从 2·n_heads·d_head 降到 2·d_latent
      ├─ 推理速度显著提升
      └─ 数学原理:
          ├─ K_compressed = K · W_down
          ├─ K_rope = RoPE(K_compressed)
          └─ K = K_rope · W_up

关键理解: MLA 如何在保持性能的同时大幅减少内存
时间: 3-4小时（重点理解 MLA）
```

#### **FFN 变体**
```
核心问题: DeepSeek-V3 的 FFN 有什么特别？
学习要点:
  ├─ SwiGLU 激活函数
  │   ├─ Swish + GLU (Gated Linear Unit)
  │   ├─ FFN(x) = (xW₁ ⊙ swish(xW_gate)) W₂
  │   └─ 性能优于 ReLU/GELU
  └─ DeepSeekMoE (混合专家)
      ├─ Sparse MoE 架构
      ├─ 每个 token 只激活部分专家
      ├─ 计算效率高
      └─ 模型容量大

与 DeepSeek-V3 的关系:
  ├─ 使用 SwiGLU 激活
  └─ 使用 DeepSeekMoE FFN

时间: 2-3小时
```
