# Day 8-10: 数据连接与向量化

## 📚 学习目标

通过3天的学习，你将掌握：

1. **文档加载器(Document Loaders)** - 加载多种格式数据源
2. **文本切割(Text Splitting)** - 智能分块策略
3. **文本向量化(Text Embedding)** - 将文本转换为向量
4. **向量数据库(Vector Stores)** - 存储和检索向量
5. **RAG基础(Retrieval Augmented Generation)** - 检索增强生成

## 🎯 为什么需要数据连接与向量化？

### 问题场景

**问题1: LLM知识有限**
- LLM的知识截止到训练时间
- 无法访问私有数据
- 无法提供特定领域的深度知识

**问题2: 上下文窗口限制**
- GPT-3.5: 4K tokens
- GPT-4: 8K/32K tokens
- 无法一次性处理大量文档

**解决方案: RAG(Retrieval Augmented Generation)**

```
用户问题
    ↓
[向量化] → 查询向量
    ↓
[向量数据库检索] → 相关文档片段
    ↓
[组合Prompt] → LLM生成答案
```

**核心优势**:
- ✅ 访问外部知识库
- ✅ 信息实时更新
- ✅ 可追溯来源
- ✅ 降低幻觉(Hallucination)

## 📖 核心概念

### 1. Document Loaders(文档加载器)

#### 什么是Document？

```python
from langchain_core.documents import Document

doc = Document(
    page_content="这是文档内容",  # 主要内容
    metadata={                     # 元数据
        "source": "example.txt",
        "page": 1,
        "author": "老王"
    }
)
```

**Document结构**:
- `page_content`: 文本内容(必需)
- `metadata`: 元数据字典(可选，但很重要)

#### 常用加载器

| 加载器 | 用途 | 依赖 |
|--------|------|------|
| `TextLoader` | 纯文本文件 | 无 |

| `GitLoader` | Git仓库 | GitPython |
| `UnstructuredFileLoader` | 通用文件 | unstructured |

### 2. Text Splitters(文本切割器)

#### 为什么要切割？

1. **Token限制**: Embedding模型有最大token限制
2. **检索精度**: 小块更精准，大块更全面
3. **成本控制**: 只检索必要的片段

#### 切割策略

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每块大小(字符数)
    chunk_overlap=50,      # 块之间重叠
    length_function=len,   # 长度计算函数
    separators=["\n\n", "\n", " ", ""]  # 分隔符优先级
)
```

**关键参数**:
- `chunk_size`: 块大小(推荐200-1000字符)
- `chunk_overlap`: 重叠部分(推荐10-20%的chunk_size)
- `separators`: 分隔符列表(从粗到细)

#### 切割器对比

| 切割器 | 特点 | 适用场景 |
|--------|------|----------|
| `CharacterTextSplitter` | 按字符数切割 | 简单文本 |
| `RecursiveCharacterTextSplitter` | 递归按分隔符切割(推荐) | 通用场景 |
| `TokenTextSplitter` | 按Token数切割 | 精确控制Token |
| `MarkdownTextSplitter` | 保留Markdown结构 | Markdown文档 |
| `PythonCodeTextSplitter` | 保留代码结构 | Python代码 |
| `SpacyTextSplitter` | 按句子切割 | 需要语义完整性 |

**最佳实践**:
```python
# 通用推荐: RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", "!", "?", "，", " ", ""]
)

# 代码文档: 保留代码结构
from langchain.text_splitter import PythonCodeTextSplitter
code_splitter = PythonCodeTextSplitter(chunk_size=1000)

# Markdown: 保留标题层级
from langchain.text_splitter import MarkdownTextSplitter
md_splitter = MarkdownTextSplitter(chunk_size=500)
```

### 3. Text Embeddings(文本向量化)

#### 什么是Embedding？

将文本转换为固定长度的向量(一组数字)，相似的文本在向量空间中距离更近。

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 单个文本
vector = embeddings.embed_query("你好")
print(len(vector))  # 1536维向量

# 批量文本
vectors = embeddings.embed_documents([
    "文本1",
    "文本2",
    "文本3"
])
```

#### 常用Embedding模型

| 提供商 | 模型 | 维度 | 价格(USD/1M tokens) |
|--------|------|------|---------------------|
| OpenAI | text-embedding-3-small | 1536 | $0.02 |
| OpenAI | text-embedding-3-large | 3072 | $0.13 |
| OpenAI | ada-002 | 1536 | $0.10 |
| HuggingFace | all-MiniLM-L6-v2 | 384 | 免费(本地) |
| 智谱AI | embedding-2 | 1024 | ¥0.0005/千tokens |

**选择建议**:
- **低成本**: text-embedding-3-small 或本地模型
- **高精度**: text-embedding-3-large
- **中文优化**: 智谱AI、千问等国产模型
- **离线需求**: HuggingFace本地模型

### 4. Vector Stores(向量数据库)

#### 核心功能

1. **存储向量**: 保存文档和对应的向量
2. **相似度检索**: 根据查询向量找到最相关的文档
3. **元数据过滤**: 基于metadata筛选

#### 向量数据库对比

| 数据库 | 类型 | 特点 | 适用场景 |
|--------|------|------|----------|
| **Chroma** | 嵌入式 | 轻量、易用、开发友好 | 开发/小型项目 |
| **FAISS** | 嵌入式 | Meta开源、高性能 | 高性能检索 |
| **Elasticsearch** | 服务器 | 成熟、全文检索+向量 | 企业级应用 |
| **Milvus** | 服务器 | 专业向量库、分布式 | 大规模生产 |
| **Pinecone** | 云服务 | 托管服务、免运维 | 云原生应用 |
| **Qdrant** | 服务器 | 高性能、过滤能力强 | 复杂查询 |

#### Chroma使用示例

```python
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

# 创建向量库
vectorstore = Chroma.from_documents(
    documents=docs,                    # Document列表
    embedding=OpenAIEmbeddings(),      # Embedding模型
    persist_directory="./chroma_db"    # 持久化目录
)

# 相似度检索
results = vectorstore.similarity_search(
    "查询文本",
    k=3  # 返回Top-3
)

# 带分数的检索
results_with_scores = vectorstore.similarity_search_with_score(
    "查询文本",
    k=3
)
```

#### FAISS使用示例

```python
from langchain_community.vectorstores import FAISS

# 创建FAISS索引
vectorstore = FAISS.from_documents(
    documents=docs,
    embedding=OpenAIEmbeddings()
)

# 保存和加载
vectorstore.save_local("faiss_index")
vectorstore = FAISS.load_local(
    "faiss_index",
    OpenAIEmbeddings(),
    allow_dangerous_deserialization=True
)
```

**选择建议**:
- **开发/原型**: Chroma(简单易用)
- **高性能需求**: FAISS(快速检索)
- **企业级**: Elasticsearch/Milvus(功能完善)
- **云服务**: Pinecone(免运维)

### 5. RAG基础

#### 标准RAG流程

```python
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.chains import RetrievalQA

# 1. 加载文档
from langchain_community.document_loaders import TextLoader
loader = TextLoader("data.txt")
docs = loader.load()

# 2. 切割文档
from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(chunk_size=500)
splits = splitter.split_documents(docs)

# 3. 创建向量库
vectorstore = Chroma.from_documents(
    documents=splits,
    embedding=OpenAIEmbeddings()
)

# 4. 创建检索器
retriever = vectorstore.as_retriever(
    search_kwargs={"k": 3}  # 检索Top-3
)

# 5. 创建QA链
qa_chain = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-3.5-turbo"),
    retriever=retriever,
    return_source_documents=True  # 返回来源文档
)

# 6. 提问
result = qa_chain.invoke({"query": "问题"})
print(result["result"])          # 答案
print(result["source_documents"]) # 来源
```

#### 检索策略

**1. 相似度检索(Similarity Search)**
```python
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 3}
)
```

**2. MMR(最大边际相关性)**
```python
# 平衡相关性和多样性
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 3,
        "fetch_k": 10,      # 先取10个
        "lambda_mult": 0.5  # 多样性权重(0-1)
    }
)
```

**3. 相似度阈值**
```python
retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={
        "score_threshold": 0.8,  # 相似度阈值
        "k": 3
    }
)
```

#### 提升RAG效果的技巧

**1. 优化文本切割**
```python
# 调整chunk_size和overlap
splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,      # 较小的块提高精度
    chunk_overlap=50,    # 重叠保证上下文连贯
    separators=["\n\n", "\n", "。", " "]
)
```

**2. 使用元数据过滤**
```python
# 添加丰富的元数据
doc = Document(
    page_content=content,
    metadata={
        "source": "doc1.pdf",
        "page": 5,
        "chapter": "第三章",
        "date": "2025-01-09"
    }
)

# 基于元数据检索
results = vectorstore.similarity_search(
    "查询",
    filter={"chapter": "第三章"}
)
```

**3. 混合检索(Hybrid Search)**
```python
# 结合全文检索和向量检索
from langchain.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever

# 向量检索器
vector_retriever = vectorstore.as_retriever()

# 关键词检索器
bm25_retriever = BM25Retriever.from_documents(docs)

# 组合检索器
ensemble_retriever = EnsembleRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    weights=[0.7, 0.3]  # 向量70% + 关键词30%
)
```

**4. 重排序(Re-ranking)**
```python
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor

# 使用LLM提取最相关部分
compressor = LLMChainExtractor.from_llm(llm)

compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=retriever
)
```

## 🔧 实践建议

### 参数调优

**chunk_size选择**:
- 短问答: 200-500字符
- 长文本理解: 500-1000字符
- 代码文档: 1000-2000字符

**k值(检索数量)选择**:
- 精确问答: k=1-3
- 综合分析: k=5-10
- 成本考虑: k越大，Token消耗越多

**相似度阈值**:
- 严格: 0.8+
- 平衡: 0.6-0.8
- 宽松: 0.4-0.6

### 性能优化

**1. 批量处理**
```python
# 批量embed,提高效率
embeddings.embed_documents(texts)  # 而非循环embed_query
```

**2. 缓存Embedding**
```python
from langchain.embeddings import CacheBackedEmbeddings
from langchain.storage import LocalFileStore

store = LocalFileStore("./cache/")
cached_embedder = CacheBackedEmbeddings.from_bytes_store(
    underlying_embeddings=OpenAIEmbeddings(),
    document_embedding_cache=store,
    namespace="my-namespace"
)
```

**3. 增量更新**
```python
# 添加新文档
vectorstore.add_documents(new_docs)

# 删除文档
vectorstore.delete(ids=["doc1", "doc2"])
```

## ⚠️ 常见问题

### Q1: 向量库选择困惑?

**开发阶段**:
```python
# Chroma - 简单快速
vectorstore = Chroma.from_documents(
    documents=docs,
    embedding=embeddings,
    persist_directory="./db"
)
```

**生产环境**:
- 小规模(<10万文档): FAISS
- 中规模(10万-百万): Elasticsearch
- 大规模(百万+): Milvus/Pinecone

### Q2: 检索效果不好?

**问题诊断**:
1. 查看检索到的文档是否相关
2. 检查chunk_size是否合适
3. 尝试不同的检索策略(MMR、混合检索)
4. 优化问题表述(Query Rewriting)

**示例: Query Rewriting**
```python
from langchain.chains import LLMChain
from langchain_core.prompts import PromptTemplate

# 优化用户问题
rewrite_template = PromptTemplate.from_template(
    """将下面的问题改写得更清晰、更适合检索:

原问题: {question}

改写后:"""
)

rewrite_chain = LLMChain(llm=llm, prompt=rewrite_template)
optimized_query = rewrite_chain.run(question=user_question)
```

### Q3: Embedding成本太高?

**降低成本策略**:

1. **使用更便宜的模型**
```python
# text-embedding-3-small替代ada-002
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"  # $0.02/1M tokens
)
```

2. **本地模型**
```python
from langchain_community.embeddings import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)
```

3. **缓存Embedding**
```python
# 避免重复计算
cached_embedder = CacheBackedEmbeddings.from_bytes_store(...)
```

### Q4: 如何保证数据新鲜度?

**增量更新策略**:
```python
# 定时更新
def update_vectorstore(new_docs):
    # 1. 加载新文档
    docs = loader.load()

    # 2. 切割
    splits = splitter.split_documents(docs)

    # 3. 添加到向量库
    vectorstore.add_documents(splits)

# 删除过期数据
vectorstore.delete(ids=old_doc_ids)
```

## 📊 向量库对比详解

### Chroma

**优点**:
- ✅ 安装简单，零配置
- ✅ API友好，易于上手
- ✅ 支持持久化
- ✅ 内置元数据过滤

**缺点**:
- ❌ 性能不如FAISS
- ❌ 不适合超大规模

**使用场景**: 开发、原型、小型应用

### FAISS

**优点**:
- ✅ 性能极高
- ✅ Meta开源，社区活跃
- ✅ 支持GPU加速

**缺点**:
- ❌ 仅支持相似度检索
- ❌ 元数据过滤能力弱
- ❌ 需要手动管理索引

**使用场景**: 高性能检索、批量处理

### Elasticsearch

**优点**:
- ✅ 成熟稳定
- ✅ 全文检索+向量检索
- ✅ 强大的过滤和聚合
- ✅ 分布式支持

**缺点**:
- ❌ 部署复杂
- ❌ 资源消耗大

**使用场景**: 企业级应用、混合检索

### Milvus

**优点**:
- ✅ 专业向量数据库
- ✅ 高性能、分布式
- ✅ 丰富的索引类型

**缺点**:
- ❌ 学习曲线陡峭
- ❌ 运维成本高

**使用场景**: 大规模向量检索、生产环境
